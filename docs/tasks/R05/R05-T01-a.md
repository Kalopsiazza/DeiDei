## 2. 首版玩法策划

四个内置模式互斥，每个模式都能叠加八项技能开关。默认选择经典、技能全部开启。修改某模式的默认参数或开关后显示“经典·自定义”“火力·自定义”等；恢复与该模式默认值完全相同时自动恢复预设名称。实验标识表达平衡仍会调整，不能用于豁免非法出牌、重复扣费或不同客户端结果不一致。

| 模式 | 首版玩法 | 玩家要看见的说明 |
| --- | --- | --- |
| 经典 `classic` | 原 classic-1.0.1；开局 0 DD，一次攒 1 DD，无幸运转换。 | 默认体验，八技能开关可自定义。 |
| 火力 `firepower` | 默认一次攒 2 DD，可选 5 DD；开局仍 0 DD。 | 更快取得攻击资源；费用与攻击强度保持原规则。 |
| 贷款 `loan` | 每局活跃参赛者以 1 DD 开始；一次攒 1 DD。 | “每局以 1 DD 开始，本版无需还款。”不加入负余额、利息或欠款对象。 |
| 幸运 `lucky` | 每次适用攻击有 25% 概率成为链中下一种攻击，只发生一次。 | 按原入口支付，实际变招公开解释；更高档攻击对不同防御未必更有利。 |

首版 UI 只开放火力 2/5 两档，贷款固定 1 DD、幸运固定 25%。以后调平衡修改预设版本即可。教程继续使用经典全开；玩家保存的实验规则不影响既有教学脚本。

### 火力的连带效果

修改的是“攒效果”的收益：普通 Charge，以及历强失败且拍开始 DD=0 时的攒效果，都使用 2/5 DD。吸收或云取消这整次增长，不扣原余额；每个吸收者从每个攒者取得同样 2/5 DD，多个吸收者不分摊。云仍只产生一雷电。田利军仍在原结算阶段清空攒者最终 DD，小贝与攒的关系保留。普通攻击支出、攻击强度和吸收攻击的收益不乘倍。

验算例：2 DD 档，A 原有 1 DD 出攒，B 原有至少 1 DD 出吸收；A 最终仍有 1 DD，B 先花原费用 1 DD，再取得 2 DD。不能把 A 的已有 DD 也扣掉。

### 贷款的发放时点

“每局”指 core 的 game：首次开场、淘汰后存活者另起一局、好友房弃权导致存活者重建，都从 1 DD 开始。同局续拍、读取视图、重试、重新订阅和断线恢复都不再发放。曾义清空 DD 后不补发；淘汰者不复活、不再领取。其他资源、次数和历史照原规则重置。

把两条重开路径纳入同一个初始化方法：core `restart_survivors` 和 `room.py` 弃权后的 `new_match(survivors, ...)`。揭晓仍显示上一拍真实账目，下一局显示开局 1 DD；调整现有“资源归零”文案。

### 幸运的完整顺序

固定链：`Bi → Pragon → Three → Volvo → BigBi`，BigBi 封顶。四条可转换攻击分别花原入口费用，抽中后实际强度为 12/18/24/30 个 sixths；不追加高阶费用，不退还原费用。原入口不合法时直接拒绝，不能靠抽奖免除资格。

普通攻击、BombPragon/BombVolvo、FreeThree、张新伟复制出的上述固定攻击使用同一条链。炸药来源仍没有被吸收攻击的 DD 收益；雷电和复制来源按变招后的实际强度计算相应收益。曾义赠送的大 bi、复制的大 bi 都封顶不抽。

削、聂湘、自 bi、历强、两贝、旋转三雷、翻转沃尔沃及其派生、所有防御与资源技能、曾义和自动休整均不抽。复合招的普通攻击分支也不另抽，保留原局部试算及同分 token 语义。

结算次序：校验原资格 → 形成一次 SpendPlan → 解析复制得到 `base_move` → 使用该拍固定幸运 token 转换至 `actual_move` → 原复合选择 → 原 P2/P3/P4。保留 `entry_id` 与 `origin`；复合招仍保留完整身份和独立 `branch`。当轮攻防、匹配、吸收与反弹使用 `branch ?? actual_move`；历强比较、完整历史和复制身份使用 `actual_move`，形成高阶复制记录仍检查本轮 `attack6 >= 12`。幸运得到的 Pragon 可被下一次张新伟复制，并在那一拍独立抽一次；同一拍不递归到顶。

v2 账目记录 `entry_id/base_move/actual_move/origin` 与可空的 `upgrade={kind:'lucky_upgrade',from,to,probability_bps}`。揭晓清楚显示“雷电·三雷 → 幸运沃尔沃”及原支出。抽中不一定改善克制，例如变成大 bi 后普通防御能挡；说明不承诺必胜或必然更有利。

## 3. 规则数据、核心与好友房

### 一份规则快照，一套结算

新增纯数据规则编译模块，提供内置预设、八项关系、严格验证、默认值、归一化与 SHA-256。文件可为 `game/core/deidei_core/rules.py`、`rule_packs.py`；按职责决定，不按行数机械切分。core 不读文件、时钟、网络或系统随机，不修改进程全局常量，不复制四套 engine。

采用以下命名；若实现确有更合适的字段名，在开工阶段一次映射清楚并全链使用，不能各层猜默认值。

```ts
type SkillFlags = {
  ZengYi: boolean; ZhangXinWei: boolean; NieXiang: boolean;
  JuYan: boolean; LiQiang: boolean; Bomb: boolean;
  Cloud: boolean; TianLiJun: boolean;
};
type PackRef = { id: string; version: string; content_hash: string };
type RulesRequest = {
  schema_version: 1;
  preset_id: string;
  skill_flags: SkillFlags;
  preset_params: { firepower_charge_dd6?: '12' | '30' };
  pack_refs: PackRef[];
};
type RulesSnapshot = {
  schema_version: 1;
  rules_version: 'configured-1.0.0';
  base_rules_version: 'classic-1.0.1';
  preset_id: string;
  preset_version: string;
  skill_flags: SkillFlags;
  parameters: {
    charge_gain_dd6: '6' | '12' | '30';
    opening_dd6: '0' | '6';
    opening_scope: 'each_game';
    lucky_probability_bps: number;
    lucky_upgrade_table: 'basic-attacks-v1';
  };
  packs: PackRef[];
  rules_hash: string;
};
```

内置 `preset_id` 只接受四个已知值，`pack_refs=[]`；火力空 params 默认 12，其他内置 params 为空。包预设采用 `pack:<pack_id>:<preset_id>`，正好一个已验证 PackRef，参数来自包声明、八开关可调。未知版本/字段/能力/引用、缺失或非布尔技能值一律拒绝。DD 继续用整数 sixths 与规范十进制字符串，1 DD=6，不增加库存封顶或改成浮点。

归一化结果全字段明确。canonical JSON 为 UTF-8、递归排序对象键、固定数组次序、无空白、无浮点；`rules_hash=sha256:<64位小写hex>` 覆盖版本、预设身份、技能、运行参数和包引用，排除自身。昵称、时钟、房间时限、随机种子和本地翻译不入摘要。包 `content_hash` 覆盖归一化完整 manifest，含作者与文案；同一包文案改变会改变内容身份。只保留这两个摘要，不另造第三种行为摘要。Python/JS 使用共同的黄金向量；服务端仍独立重算，不信客户端自报 hash。

### 每拍选择、回退与进程生命周期

新增轻量 `OpponentProvider`、`LegacyModelProvider`、`legacy_projection.py`、`ai_supervisor.py`，保留原 RandomLegalProvider。直接读取原 policy 分布，不调用旧 `choose_rl_move/strategy` 的静默 Easy/均匀回退，也不搬旧规则启发式或旧simulate_turn做结算。

每拍先用当前 `list_options` 计算31槽合法 mask，再做一次真实forward。MaskablePPO可显式传mask；普通PPO读分布后同样过滤。响应31维、有限、非负；非法槽置0，剩余质量归一化，再抽一次。关闭云时 E09/E30/E31 概率为0。先固定bot决定，再接受玩家选择；get_view和重复提交不重抽。最终仍经现 core 校验。

强制休整由core决定，来源为 `forced_recovery`。本拍所有失败共用一次 `fallback_used` 预算：分布错、合法质量为0或无映射交集时随机回退一次；模型决定被core拒绝且尚未用回退时也可用这一次。已经来自 `legal_fallback` 的决定再被拒绝，直接保留未改状态报错。不能替换玩家选择或重抽幸运；玩家输入错误、旧回合和坏状态不当AI重试。模型/回退计数与最终来源只按实际成功提交的决定记录，被拒模型候选不计正常模型拍。

准备页使用可取消的非阻塞预热/status，冷加载初始上限30秒，实际测量后可有理由地调整；不延长所有WorkerBridge请求。main持有候选port和prepare generation，预热的runtime/AI在start成功时被接管，不再调用原start中的bridge.stop而重复冷加载。prepare/status使用独立严格reply，不能走当前强制view.source=live的通用call。新规则/session验证成功后才换port、结束旧空闲实例；活动对局/房间仍按原正常离开流程处理，不同时开放两个可玩局。取消或失败只清理该候选，旧回复不能复活它。

热推理从父进程发请求起限750ms；timeout/crash/断管只终止AI child，core session继续，当前场余下使用随机策略。可恢复单拍异常可下拍再试，连续两次后本场降级；不在牌局里反复冷启动。

AI常驻独立CPU进程，使用eval/inference模式，初始线程预算1。源码专用AI Python路径只由main开发配置提供，成包走固定资源；shell=false，隔离cwd/user-site/PYTHONPATH。请求关联generation、decision_id、expected_turn、rules_hash，迟到回复丢弃。离开、取消、新场、main/runtime异常结束都回收本应用拥有的AI后代。POSIX进程组仅用于定向结束，还需独立guardian/EOF租约等父死亡监督；Windows使用关闭即回收且句柄不泄漏的Job Object或经实测等价方法。分别直接终止main和runtime，证明所属AI不残留，不能依赖强杀时执行finally；不结束其他线程的进程。

UI读取真实 `requested_id/active_id/state/compatibility/model_turns/fallback_turns`。预热失败提供重试或明确选择随机；每拍揭晓区分 `legacy_model/legal_fallback/forced_recovery`。模型路径、hash、概率与traceback留本地诊断。正常策略不会主动输出新增两张曾义牌；真实回退可从当前全部合法入口选牌，并如实标来源。

原模型加载和真实forward放在本包早段探查。至少完成默认、禁云、玩家曾义后的真实模型调用与现core结算、一次正常桌面对局、一次受控回退；采冷启动和约200次热请求p50/p95/max、RSS与超时数。这些测量不代表模型强度评估。模型仍无法加载时此项标未完成，其他步骤继续，不能用随机对手作为通过证据。

### 同意、撤回与在飞数据

固定桥接：read、setScope（单scope布尔＋expectedRevision＋expectedStateToken）、stop、preview、setLocalRecording、clearLocal、deleteUploaded。renderer不能全量覆盖隐私文件、提交任意JSON、URL或凭据。公开状态区分persistedScopes与effectiveScopes，带持久revision和本进程stateToken；只采纳不旧于当前状态的回执。

开启：验证当前revision/token → 串行原子提交新scope、epoch和空outbox → 再确认没有更新的stop → 后台授权登记ACK → 开启发送门。关闭某scope或stop：任何await前先关发送门、更新stateToken并abort → 再串行持久化关闭、新revision/epoch、清旧outbox → 发不含统计的撤回控制请求。改变任一scope均换epoch并放弃旧待传汇总，另一已开启scope从新观察继续。

较早的enable写入即使先完成，也不能越过较新的stop重新开门。产生观察、入队、request.write/end之前及ACK/retry处理时都检查有效scope/epoch/token；后台把验权、日记录写入、撤回、删除安排在同一事务序列。已被服务器接收的数据无法由abort收回，删除操作另行处理。ACK只移除对应report_revision的待发版本，不吞掉请求期间新累计的计数。

停传写盘失败时，本进程effectiveScopes仍关闭，UI显示“本次已停止，关闭选择尚未写入，请重试”，明确下次启动可能仍读到原保存值；不声称永久停止成功。下次启动若文件不可验证、不可写或密钥不可取，先保持上传关闭。全部持久写失败时无法保证断电后状态变化，记录此实际情况；修复写入重试后验证冷启动仍关闭。

首次主动同意才生成独立随机installation_id与能力密钥，不复用档案或硬件标识；main用Electron safeStorage保护凭据，后台只留摘要。损坏或解密失败不恢复为默认同意。删除成功后再同意生成新身份。清本地记录、恢复profile均不随意丢失仍用于删除旧报告的凭据。

提供实际调用管理路由的CLI和可读表，token从私有文件或秘密管理读取，不放命令参数/URL/客户端包。后台按installation+epoch+scope+day+app_version识别报告；同report_revision同内容重试只计一次，异内容拒绝；新revision替换，旧revision不回滚。当前选择每个安装取最新有效快照，不能连续七天算七个人；使用量按每日计数计算。采用参数化SQL、有限body/并发/队列/busy_timeout和错误响应；DB失败不能回成功。

后台贡献保留90天，删除与撤销摘要同事务，最小撤销摘要保留180天，旧能力不能通过reports自动注册。删除后聚合结果立即重算；服务重启后去重、同意和删除继续成立。若提供备份模板，最多7天，恢复前重放删除记录；已主动导出的离线CSV不能由游戏开关收回，说明写清。

### 本机画面推荐

main在ready后读取RAM、可用并行度与Electron GPU合成状态，使用白名单投影；不将完整getGPUInfo对象给renderer，不执行系统扫描命令。查询超时或失败为unknown，不能凭GPU/CPU名字声称测得性能。

建议算法v1：软件合成或RAM≤4GiB建议smooth；其余先balanced，unknown标明信息不足；保留既有custom和用户手选。高核数/大内存不自动high。页面给出理由、“应用到草稿”“保持当前”和“在本机测一测”。推荐只改graphics草稿，经正常保存生效，不改卡牌/规则；换屏、重启只让建议过期，不重写保存值。系统减少动态/透明继续优先。

可选短测在非对局当前可见场景运行，约2秒稳定＋8秒采样，UI可取消。使用rAF回调间隔摘要，明确它不是屏幕呈现FPS。失焦、隐藏、最小化、尺寸/DPR/显示器/系统偏好变化使样本无效；不关后台节流凑成绩。临时样本最多4096，结束/取消丢弃，落盘仅摘要。

只有实际在high效果下取得有效样本，才可建议保留高质量；首版参考条件为硬件合成可用、RAM>4GiB、有效样本≥240、p95≤20ms且>50ms间隔比例≤1%。这些是待调产品阈值，只说明当前场景与负载；没有测high时不从balanced短测外推。报告记录实际画面组合、窗口内容尺寸、DPR、系统偏好和有效性。不开上传仍能完成本机建议和短测。

### 更新页与主进程

UpdateService单实例拥有候选、版本、状态、下载、缓存与安装计划，UI只消费快照。UpdatePreferences独立原子保存：自动检查默认开、自动下载默认关、渠道默认stable；控件立即保存，原设置放弃动作不回滚它。关自动检查后手动检查仍可用；开启自动下载后真实拉取合格候选。启动后错峰检查，后台间隔约6小时并退避，牌局中只轻提示，不抢焦点。

main使用独立更新网络session与构建时受信配置，保留renderer的app://、CSP、senderFrame、sandbox、contextIsolation、证书验证。逐跳检查来源和实际所需HTTPS/CDN主机、repo、OS/arch、合法asset名、大小和semver，拒绝凭据URL、路径穿越、file/远端http/任意重定向。生产未配置或dev/旧portable不支持时显示确切原因；隔离fixture才允许脚本自开的回环feed，不能通过renderer/env放开生产任意地址。

### 渠道与缓存

stable对应latest，只接受无prerelease的semver；beta接受beta以及更高正式版，不收alpha/rc。每次设置channel/allowPrerelease后，最后显式重设allowDowngrade=false，再独立比较版本。`0.4.0-beta.1 → stable`若最新正式版只有0.3.9，保存渠道但继续现版，说明等待新正式版；不自动降级。tag、package版本、Release标志、渠道元数据相符。

并发check/download去重；切渠道作废旧候选、取消下载与安装计划，用generation/revision拒绝迟到事件。同版本异hash报错。缓存不等于安装许可：重启后由updater重新验证才恢复ready，无网时保留缓存和离线游戏能力，不盲装。一次安装确认不跨启动保存。字节损坏、截断或无空间不进入ready；ready表示下载与hash/size校验完成。Mac原生发布者校验发生在明确安装后的staging，不能在ready就称已验签；原生验签失败不得替换或启动新版本。

### 安装前的退出处理

玩家明确选择“现在安装”或“回到主菜单后安装”，后者可取消且只在本次运行有效。对局、教程、房间大厅、断线重连、结算/进出动画、正在保存或未保存草稿都暂缓安装；更新器不主动踢人离房。

新增小型shutdown coordinator复用现有退出流程。main发一次性nonce/generation的prepareRestart；UI在主菜单且无过渡、弹窗、仍开放且未保存的规则/设置编辑时回ready，有草稿则走保存/放弃/取消。保存成功或确认放弃后结束编辑事务并清dirty；已应用局前配置、取消编辑后的模式缓存、立即保存的隐私/更新偏好不属于未保存草稿。main再独立检查port、房间、start/switching、store和AI任务，不能仅看result时已false的WorkerPort.active。过期nonce、reload、失联、超时均不能触发安装。

最终建立一次性重启状态，拒绝新开局/进房及普通存储命令，重新确认。用独立restartSuspended暂关上传发送门并abort，不改保存的同意；取消更新只解除restartSuspended，绝不从旧persistedScopes重建发送门或清掉玩家stop。native交接前privacy.stop/撤回仍可执行并作废旧prepareRestart ACK。等待已发起隐私写盘，绝不等遥测网络ACK；停传未成功落盘时取消此次更新，运行态继续停传。完成写盘、备份及core/AI/闲置连接清理后，在同一个无await步骤重查token、记录不可取消的交接状态、调用native quitAndInstall。交接后不接受需异步落盘的新设置并承诺能阻止重启。调整现main before-quit逻辑，避免普通app.quit抢走native流程或重复安装；session-end不新启安装。

准备/保存阶段失败可以解除准备状态重试；一旦调用native quitAndInstall便关闭取消入口，记录单次接管，不把void调用当完成。native明确报错时保留旧应用和可恢复提示；所锁版本若没有可靠公开重置方法，重开游戏后才允许再次native安装，不能在同进程反复叠加Mac的update-downloaded监听。增加坏签名失败→重试有效包的真实场景，检查无重复退出或迟到安装。

已查到的稳定线MacUpdater源码在autoInstallOnAppQuit=false时先下载到缓存并建立本机proxy，直到quitAndInstall才让native updater取得文件；实施仍要用实际锁定版本验证“下载完成→普通退出再开仍旧版”。Windows NSIS不承诺事务式替换或自动回滚；保留重取完整安装器及恢复说明。

### 成包与更新实测

保留app://白名单及两套完整牌面。验证第一方stage、生产依赖、core/AI可执行文件、模型hash、两端catalog/entry-map、配置、许可证/署名与全部资产。应用目录只读、中文空格路径、不同cwd、无开发Python/Node仍能离线启动与真实模型出招。服务和更新配置在签名前放入正确resources，不能签后手改app。

Windows使用对应venv和分号PYTHONPATH。服务环境按 `game/server/requirements.lock` 安装；新AI和采集环境分别使用自己的精确lock，不污染现有环境。desktop test已含typecheck/build，常规微调不要反复另跑同一构建。

### 六条有界真实体验路线

1. **规则工作台→单人**：四模式和八开关、跨模式草稿/自定义/重置/命名预设；普通main+真实worker开经典、改技能的实验模式、导入样例，各自快照与账目正确。其余排列由定向core测试覆盖，不在GUI穷举256组合。
2. **旧模型→故障恢复**：真实模型正常对局/揭晓；取消预热不迟到入场；一次受控超时或坏响应走实际回退，场与UI保留；正常模型拍、回退拍、休整拍分开。
3. **好友房**：两个普通main Electron＋真实回环server，房主改规则、清准备、旧ready/start拒绝、一轮公开结算、断线恢复、回大厅；再用同一进程组运行导入包。测试观众投影与重开可用真实服务定向用例，不需重复全6人长跑。
4. **同一次设置会话**：卡牌/画面/身份草稿跨分类、保存/放弃/失败；采用推荐、短测与失效；隐私开关与旧回执交错；真实collector可见数据、停止与删除；更新状态不因切分类丢失。
5. **原生更新**：隔离fixture N→N+1实际下载/校验/安装/重启；实际活动房间与草稿暂缓、取消安装计划、普通退出不偷装；合成档案和规则库跨版本保留。按平台分别记录，不能用mock代替native层。
6. **动态与输入**：复用上述场景，在同一实例连续调整内容区1366×768→1000×650→较高窗口→原尺寸，验证左右滚动/返回/应用按钮、原生键盘、弹窗焦点、错误说明增长；记录实际DPR，模拟尺寸标模拟，测试自有进程全部结束。

随这些路线保存少量同版真实Electron截图：短窗口规则/设置、发生实际幸运变招的揭晓；两种cardStyle各核对一次共享牌桌渲染，确认完整牌面比例/铺满、原版卡框、无重复标题、身份及倒计时无遮挡。截图索引记产品SHA、来源、内容尺寸、DPR、画面档与卡牌风格；截图只证明所示画面，不替代规则、模型或安装证据。

可以用MOCK或固定token注入难触发错误、供可复现单测；证据清楚标用途。真实房间证据来源为普通main与socket，模型证据来源为原权重，更新证据来源为真实字节与native接管。没有做跨电脑、真人、跨DPI、签名信任或性能归因的项目继续写未运行/未定位，不借本包测试数量宣告通过。
