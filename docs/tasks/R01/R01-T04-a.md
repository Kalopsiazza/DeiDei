## 检查顺序

1. 记录Windows版本、x64/ARM64、分辨率与缩放，当前Python/Node是否已安装。ARM Windows上的模拟运行另标，不代表x64原生笔记本。
2. 跑W01—W04：中文目录双击、素材/6席位/Health；四固定案例应依次 Continue / PlayerWin / Continue / PlayerWin；seed42两次Easy一致并标Easy heuristic。用虚构昵称写档案，重启读取；空昵称与非法seed失败、已有档案仍保留。
3. 跑W05：完整启停10次，记录本程序与worker路径/PID、退出后是否消失；停止worker再Health恢复。只结束本次进程。不能把测试器自身node进程当成应用依赖系统Node的证据。
4. 同学先完整关闭程序，再手动断网，按照提前保存的步骤重做启动/素材/档案/案例/Easy，然后恢复网络。这项由人确认，自动屏蔽请求不算物理离线。
5. 有真正无Python/Node的设备或干净虚拟机才做W07；否则NOT_RUN。采集实际缩放、普通权限与安全提示。破坏档案等异常只在独立测试副本做，不能改私人文件。
6. 有精力且环境允许，再执行下面的固定源码回归与原生构建。已完成的下载包检查单独保存，不因为构建等待而不提交。
