## 先打开，再迭代

先读根 `AGENTS.md`、本任务、`game/desktop/README.md` 与 `game/desktop/package.json`。在用户实际系统上启动现有 Electron 应用，让 Teddy 看到主菜单并进入真实单人局；对手当前是临时随机对手，别称作训练模型。暂时只看主菜单也可立即开始视觉修改，不要求先完成一局测试。

已有源码入口是仓库根目录下的 `npm --prefix game/desktop start`，它会先构建再启动 Electron。离线 worker 需要 Python 3.11+，通过 `DEIDEI_PYTHON` 指向已可用解释器；优先沿用现有环境，只有缺依赖才安装锁文件中的依赖。具体步骤见桌面 README，别运行根目录旧 Tkinter 启动器。未配置联机服务不影响先做离线前端。

首个可见结果是本机真实窗口及可重复启动方式。若重复 start 妨碍迭代，再用现有 esbuild 加轻量开发监听／刷新，让 renderer 改动方便预览；涉及主进程的改动可明确重启。不要为了热更新另建一套网站或迁移框架。开发监听只在本机，退出时结束自己启动的子进程，不影响其他线程。

## 可以直接做什么

`game/desktop/` 中的页面、React 部件、样式、卡框、图标、文字层次、现有操作的视觉反馈及轻量演出，可以跟随 Teddy 的意见连续修改。可以整理当前页面的重复代码、增加本地素材及必要的开发脚本，不要求每次重新获批。当前样式与 33 个招式入口仅作内容参照，排布可以变；所有入口仍能访问，不能为了画面好看漏掉招式、费用或关键状态。

手绘、涂鸦、暖纸面是已有偏好，像素风曾被放下；Teddy 随时可以换方向，不需要把整套风格一次选完。缺少旧参考图时继续用真实页面和已知偏好，不等待找回附件。先围绕他正在看的页面做一版，再听反馈，别先发长问卷。使用生图工具时以实际产物为准；没有工具就如实说明，用已有素材和程序图形继续。

沿用真实单人 worker 与既有房间行为。缺少合适局面时可使用醒目标明的开发预览，示例不写入用户档案、不伪称真实联机；局部静态试图只能辅助，主要修改落回真实页面。
