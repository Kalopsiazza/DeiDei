# 叠叠｜规则引擎设计 1.0

作者：ChatGPT（规划）　日期：2026-09-12  
依据：[经典规则规范 1.0](../rules/v1/RULEBOOK.md)。本文件是供后续 Codex 实现的程序设计，当前没有新引擎代码，也没有发出实现工作包。桌面与联网的最终技术选择仍需结合任务 02 的证据。

## A01｜设计目标与职责

规则核心接收固定局面和本轮选择，输出可复查的逐人结果。它不创建窗口、不读本机档案、不请求网络、不调用 AI、不播放动画、不自行读取时钟。相同局面、动作和选择随机输入，得到相同结果。

职责分为：招式定义与选牌资格、来源解析、分支选择、条件与属性生成、P2 原始作用、P3 回击、P4 账目、整场推进。前述部分可以在没有美术和模型的环境里验证。有限的 26 种实际招式采用清楚的规则函数及数据表，不把讨论 JSON 做成任意效果脚本解释器。

旧 `MOVE-CATALOG.json` 的 value/status/evidence 包装用于证据，禁止直接作为运行规则。旧 `deidei_env.py` 和模型也不提供新版胜负答案。原文件保留；新核心放在后续工作包指定的新目录。

## A02｜数值表达（规划选择 D01）

本版所有有限 DD、攻击、防御数值都能用 1/6 单位精确表示。选用整数六分之一单位保存：1/3→2，1/2→3，1→6，7/2→21，100→600，9999→59994，10000→60000。此项是计算表达，不改变玩家单位。

- DD、普通攻击数和有限防御数为非负整数六分之一单位；雷电、充能、层数和次数为非负整数计数。
- 防御正无穷采用独立类型 `unbounded`，不填一个“大概够大”的整数。
- 内存采用不会无提示溢出的整数；跨语言数据中的整数采用十进制字符串，解析后再算。禁止 NaN、Infinity、浮点近似以及布尔值冒充数值。
- 格式示意：有限强度 `{"kind":"finite","sixths":"21"}`；无穷防御 `{"kind":"unbounded"}`。DD 与强度有不同字段，不能互相直接替代。
- 不把旧 AI 的观察截断值当成游戏资源上限。不设置未经讨论的资源封顶。通信长度限制属于防异常输入措施，另在通信设计中说明。

## A03｜标识与类型

所有动作以稳定字符串标识；不得把界面第几个按钮或旧 AI 动作下标当成实际招式。`entry_id` 表示本次入口，`move_kind` 表示完整实际原招，`branch_kind` 表示本轮选中的效果。旧标识映射放在临时 AI 适配处，与新核心分离。

`origin` 只用当前五种值：`normal / bomb / lightning / zhang / zeng_reward`。复制不形成可嵌套的历史来源链。防御匹配读取当前攻击类别，历强及上一招记录读取完整 `move_kind`。

### 持久数据

| 对象 | 所需字段与职责 |
| --- | --- |
| MatchState | rules_version、match_id、初始参赛身份集合、仍参赛身份集合、game_id、turn_index、每人 GameState、本场淘汰与结果；回合从 1 开始 |
| GameState | dd、lightning、nx_charge、mature_bombs、pending_bombs、bomb_placement_count、cloud_uses、tian_uses、zhang_used、liq_used、enhanced_xiao、last_actual_move、latest_copyable_move、zeng_state、reward_due_turn |
| PendingBomb | 放置的本局编号、回合编号、成熟回合末；每次放置一份，不能借旧局时间在新局成熟 |
| ZengState | unused / recovery / waiting / ready / spent；reward_due_turn 只在 waiting 有值 |
| MoveDefinition | 完整招式、阅读分类、固定攻击参数、可能的条件或分支、防御数与比较方式、匹配处理、各效果所处阶段 |
| EntryDefinition | 入口、来源解析方式、资格与支出计算方式；张新伟在此读取自己的有效高阶记录 |

完整对局日志可以另行保存，不参与恢复已清掉的玩法历史。房间、昵称、头像、观众、缺席计数、房主信息及网络连接不属于 GameState；新开一局不能把这些数据清掉。

### 只存在于本轮的数据

| 对象 | 所需字段与职责 |
| --- | --- |
| RoundInput | 规则版本、match/game/turn 标识、本轮完整开始状态、每位参战者的一份已接收入口或系统续招 |
| SpendPlan | 本入口的一笔 DD／雷电／充能／炸药／奖励支出和一次性资格变化；原招不再另扣 |
| PreparedAction | player_id、entry_id、move_kind、origin、branch_kind、是否休整、是否强化削、条件成功、合规目标集合、SpendPlan、原始攻击、防御信息、资源作用 |
| DefenseSpec | 数值、比较方式、用途（对撞／独立／持续）、有效阶段和明确的匹配处理编号；0 表示无防御 |
| EffectRecord | 唯一作用编号、阶段、作用者、目标、作用类别、适用时的数值／资源、引用规则、是否被挡及原因；直接淘汰不填伤害 |
| ReturnRecord | 原来袭编号、反弹者、原攻击者、原数值；只带回击所需信息，不复制原招全部效果 |
| RoundLedger | 完整作用、每人的一次支出和净变化、致命原因、不同击杀目标集合、本轮账目状态；不被新局初始状态覆盖 |
| MatchTransition | continue_game / restart_survivors / sole_survivor / nobody_survives，下一状态、可空赢家、淘汰身份集合 |
| RoundOutcome | RoundLedger、MatchTransition、每个选择者采用的分支和随机决定凭据；尚无动画时间线 |

PreparedAction 和阶段输入在生成后只读。中途致命效果写到 EffectRecord，不能改写本轮的参与者名单或防御属性。

## A04｜规则核心调用约定

下列签名为设计表达，不是本次实现代码。

- `list_options(state, player_id)`：根据本轮开始状态返回入口、可用性、不可用原因、实际费用和持有门槛。不得读取尚未揭晓的他人选择。
- `resolve_round(round_input, choice_tokens)`：完整有效时返回 RoundOutcome；无效时返回带原因的 Rejected，输入逐字意义保持不变。
- `advance_match(state, ledger)`：按规范 R26 产生继续、新局或结束结果；不额外再次计算攻击。
- `evaluate_fixed_view(view, fixed_actions)`：内部的无副作用求值路径，供分支试算与正式作用共用；不再调用分支选择、不读全场隐藏在外部的对象。

规则核心不决定“先到的包算哪个回合”、是否还允许改选和网络重试时缓存多久。房间层用 match/game/turn 与请求标识去重；一旦某轮已结算，再收到相同轮的请求返回已有结果，不能再次支付或抽分支。

## A05｜P1 的固定先后

1. 验证规则版本、局与回合编号、参战身份及一人一动作；观众不出现在集合中。检查局面数值合法、待成熟和奖励属于当前局、每局一次没有非法复用。
2. 根据开始状态识别曾义强制休整，校验外部输入不能替换它。为其他人验证入口资格，产生一次 SpendPlan。整轮有无效项则拒收，不提交任何变化。
3. 解析完整实际身份与本次来源。张新伟复制后保留完整原招，清楚区分其分支类别；SpendPlan 仍为张新伟入口的 0 费用。
4. 按实际 RotateThree / FlipVolvo 确定全部选择者集合，一次形成；之后别人先算完也仍是选择者。
5. 按 A06 各自选一个分支，全部完成后才恢复全场。
6. 在正式全场从头生成条件：自 bi 目标为反弹／吸收／云；历强目标为完整身份重复且非曾义休整的人。条件依身份和当前分支类别确定，不依最终是否击杀。
7. 生成原始攻击数、防御数与阶段范围、攒效果、清空、反制等计划。随后才进入正式 P2。

失败历强是否按攒只读开始 DD。成功状态不会因后来资源变化、有人受伤或分支试算结束而反复切换。

## A06｜分支求值与可复查随机（规划选择 D02）

每个选择者 i 的视图只含 i 与所有非选择者。将 i 固定为一个候选分支，保留 i 的完整实际身份与来源，对视图内所有人重新生成条件，然后执行 P2、P3 与仅计算结果的 P4。不要用正式全场已经算出的历强成功等状态代替局部重算。

评分为 `(本人存活, 本人有效击杀目标数)`，按这两个量先后比较。去重自己的目标集合，不数总死亡人数，不数击中次数，不加资源收益，也不读新局重置后的状态。

最高评分只有一个候选就采用它。并列时规划采用等概率选择，这是对已确认“同等随机”的具体实现选择。为每个 player_id 提供独立选择 token，顺序稳定的候选表消费对应 token；不能用遍历座位顺序消费一条共享随机流而改变结果。生产端的安全随机来源由运行层提供；测试直接注入固定 token。保存选定分支供重放和重试，不再重新抽取。

试算不扣资源、不增加次数、不推进炸药、不发奖励、不写历史，不创建真实新局，也不能消耗正式随机源。恢复全场后仍按已选分支执行，即使结果更差也不再次优化。

## A07｜P2 原始作用

对每个有原始数值攻击的动作，向每个其他本轮参战者生成一条来袭候选。允许改变遍历顺序，但结果相同。0 攻击动作不生成数值来袭。

每条来袭依次处理：

1. **该目标是否受到此作用。** 自 bi／历强只攻击其合规目标；两贝彼此的原始攻击取消；小贝对具有攒效果的目标不产生攻击。
2. **明确禁防和允许特例。** 大 bi 对反弹禁防、对普通防允许；两贝对三种反制与田利军禁防；聂湘对吸收／云禁防；强化削对普通防／放炸药禁防；其他匹配按规则表。
3. **一般防御。** 普通削可以被当前有效正防御挡住；普通攻击对撞用 ≤；专属防御用数值相等加类别；其他阈值照其规则。
4. **作用记录。** 没挡住则记致命攻击；被合规反弹挡住则登记 ReturnRecord；被合规吸收挡住则登记该次资源收益。不能因为目标已另有致命记录而跳过。

另行、每对只一次登记田利军／小贝的直接淘汰、纯自 bi 失败的自身淘汰、云／吸收阻止攒、吸收从每位攒者获得 1 DD、田利军清空。直接淘汰编号绑定其唯一规则，不由双方处理函数各记一份。

普通防御每次施放基础充能一份；按成功防御的独立 Bi、普通 Xiao、BigBi 来袭再逐次记录额外充能。同一来袭先生成稳定编号，不能在不同效果处理处重复奖励。

## A08｜P3 回击

只执行 P2 已登记的 ReturnRecord，一条对应一次原来袭。目标为原攻击者，数值保持原值，击杀归反弹者。双方在 P2 是否已有致命记录均不取消它。

P3 不再采用攻击的对撞防御，也不再次生成原始攻击、资源吸收或新的回击。本版无递归反弹。持续防御按规范 R06/R08 检查。

独立防御 P3 暂无合法触达路径：能触发回击的原攻击者只可能使用本版可反弹的攻击及对应来源／普通分支，均无独立盾；条件高伤超限、两贝和大 bi 被排除，其他防御动作无原始攻击。给这一断言增加自动枚举检查。将来新招破坏此条件时返回“本规则版本缺少该场景定义”并要求扩展规范，不能默认某个尚未定义的盾失效。

## A09｜P4 账目与时序

先依据开始状态和收集结果生成账目，不就地改输入对象：

- 应用每人的一份 SpendPlan；余额不足表示 P1／设计出了问题，返回明确错误，不把负余额悄悄改成零。
- 合计可吸收攻击 DD、每位攒者贡献、云的一次雷电、普通防御的基础及额外充能。攒增长由一个“本次取消”结果决定，不按云／吸收人数多扣。
- 登记合法使用次数、一次性资格、强化削的用掉／授予和完整实际历史；可复制高阶以本轮属性判断，禁复制／低强度不覆盖旧值。
- 推进当前局的炸药，成熟条件是 `mature_at_turn_end ≤ 当前回合`；本回合新放的成熟点为 `当前回合+1`。本次取不到刚成熟的层，只有下一回合的资格检查可以使用。
- 田利军清空覆盖对应攒者本轮最终 DD，但不回滚其他人的独立收益。
- 曾义发动／休整按明确清单清空有利积攒及复制资格，保留使用记录；被清掉的待成熟炸药不在以后恢复。它的本局阶段与日志不清。成熟与清空同时出现时，清空后的库存和等待均为零。
- 曾义发动 `unused→recovery`；下一回合休整 `recovery→waiting`，到期末为发动回合+4。到期末 `waiting→ready`，清掉到期值，只发一份。使用免费大 bi 时 `ready→spent`。若进入新局，由 A10 清掉这些旧局进度。
- 汇总不同击杀目标、致命原因与淘汰集合，先保存本轮最终账目，再产生 MatchTransition。

以上是单一合并过程的优先关系，不是依玩家先后来争夺余额。事件记录同时区分获得、支出、清空；例如吸收净赚 4 随后因新局归零，两件事都能查到。

## A10｜整场推进与房间分工

无淘汰同局继续。有淘汰且至少两名存活者，创建新的 game_id、turn_index=1，存活者重新建立初始 GameState；淘汰者保留整场身份与淘汰事实，不再提供选牌。剩一人为赢家；剩零人 winner=null、原因 nobody_survives。

新局只重建玩法数据。房间类型仍按整场开局双人／多人保持，不能六人剩两人就改成双人 AI 超时策略；缺席计数、本机档案和房主身份也不能跟随新局回到零。房主离开导致房间结束属于房间服务事件，不伪造一种攻击或规则赢家。

当前房间 PRD 的未定项不由本文件填写。客户端和观众只接收已经允许公开的数据，本轮尚未揭晓的选择不进入可见状态。

## A11｜临时旧 AI

临时适配输入为公开局面及当前合法入口，输出为一个候选入口。新规则核心复核合法性并独立判定结果。旧 AI 不处理胜负，也不能更改本版条件来适合旧模型。

映射失败、旧模型不支持曾义或运行依赖不可用，都要标明实际使用的对手。回退为简单策略时展示／记录回退，不声称专家模型通过。新的专门 AI 和是否重新训练留作后续项目；不会阻止固定案例验证和规则核心开发。

## A12｜可追查测试要求

[CASES.md](../rules/v1/CASES.md) 的预期由规范推导，交给 Codex 写真实测试。除此以外，后续实现包需覆盖：

- 输入在试算、成功结算和拒收后不被修改；不同玩家的列表／集合不共用可变实例。
- 玩家数组顺序任意交换，按身份整理后结果相同；并列随机使用同人同 token。
- 同一回合重试不重扣、不重抽、不重复发奖励；存档序列化再读取结果相同。
- 每对作用独立；每人每回合一次费用；同人同目标击杀去重；0 攻击无致命数值事件。
- 正式局面与局部试算不共用已经生成的条件；分支判断包含回击；全场恢复不重选。
- 26 种实际招式、33 个入口均有资格／费用／典型效果覆盖；所有可生成回击的入口都符合 A08 可达性断言。
- 曾义技能清空与新局全部重置分别测试；旧局的成熟、奖励和历史不能穿越到新局。
- 旧 AI 行为测试与规则答案分离；新增规则不能拿旧 93 个观察输出当新版真值。

完整规则实现和这些测试尚未执行。本次验收只接收任务 01 的证据与规则确认材料；正式编码仍等待新的编号工作包。
