# Teddy × ChatGPT × Codex／DeepSeek｜协作方式 v2

2026-09-29，由 Teddy 明确同意。适用于当前及后续前端试做；旧技术任务的专用要求继续有效。

## 前端日常

Teddy 说想尝试什么 → Codex／DeepSeek 直接修改真实前端 → 本地打开体验 → 继续修改或退回上一版。一个页面或一段体验值得保留时，做一次阶段提交；Teddy 说“交回审阅”时，再创建或更新同一个结果 PR。

Teddy 决定画风、页面和操作感；执行者可直接提出并尝试相应前端实现。ChatGPT 在阶段审阅时检查重复代码、状态归属、遗留试验、与已有游戏行为的配合，只做有明确收益的整理。保持用户已经喜欢的画面，不为了审阅而重写，不承诺后期审阅能替随意堆积代码兜底。

不要求每句反馈重新发包，不要求先完成整套美术规格，不要求每次等待 PR 回复，不要求先通过其他技术 PR。当前前端按 R04-T01-b 持续进行，a/b/c 仅用于工作主题或合作方式明显改变。

## 哪些变化另作技术任务

规则结算、费用与资格、存档格式、联机协议、身份、TLS、Electron 权限、依赖大改和发布部署，继续由 ChatGPT 设计、执行者实现、按影响验收。出现这类需要时记下具体事项，同时继续能独立完成的视觉工作；不让整段前端探索停下。

前端可以调整布局、样式、部件、文案、已有操作的表现和轻量演出，但保留实际判定与原有行为。交牌不可修改、倒计时依据、提交去重、恢复与观战权限等不因视觉试验改变。

## 检查的时机

| 变化 | 日常检查 | 阶段审阅前 |
| --- | --- | --- |
| 配色、纸纹、排版、卡框 | 实际打开，查看大小及相关点击 | 类型检查／构建，代表性截图 |
| 交互、状态展示、前端部件整理 | 受影响流程的针对性检查 | 对应行为测试、真实单人短局 |
| 开发监听与刷新脚本 | 冷启动、改文件刷新、关闭后子进程退出 | 无新增权限、无残留监听 |
| 规则、网络、安全等技术变化 | 按专用任务 | 相应回归，不套用视觉简化要求 |

纯外观改动不反复运行 900 秒、多房间、TLS、多平台打包。既有 CI 不关闭，不为每次微调手工追加新工作流。保留已有有效测试；外观预期随已选设计变化时解释原因。未运行不写成通过。

## 最少但有用的记录

当前任务的 `NOTES.md` 记录启动方法、这一版改了什么、Teddy 选了什么、已检查什么及已知问题。阶段留少量真实截图和可恢复提交；不要求每轮微调写 REPORT、完整 manifest、哈希清单或大批日志。

`ISSUED` 表示任务已发出；实际启动后才登记 `RUNNING`；`SUBMITTED` 只是交回；`ACCEPTED` 表示具体范围已审阅接受；`MERGED` 仍需用户另外授权。喜欢画面与代码验收分别记录。

同一工作分支每次只由一个执行线程写入；换模型时说明当前提交与未提交改动。保存并推送本任务代码已获许可；阶段 PR 不自动合并。公网、收费服务、签名／系统信任、许可证与私人素材需另外获得许可。
