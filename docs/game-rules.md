# 规则与样例

这是原始提交 `d4b943f5` 的代码行为摘要，用于协作和测试；尚不能当作高中时期全部口头规则的完整定稿。历史玩法由维护者与熟悉游戏的同学确认，AI 不自行决定。存在不同表述时在 PR 提问，并参考 [已知问题](known-issues.md)。

## 基础约定

双方每回合各出一招，一起判定结果。玩家状态默认从 0 开始。内部 `1 DD = 6` 个整数单位，避免分数资源计算产生误差；“削”消耗 2 单位，即 1/3 DD。

普通“攒”成功时增加 1 DD。招式是否可用由 `list_legal_moves` 判定；输入当前不能使用的招式，现有 `simulate_turn` 会返回继续且不正常推进该回合，这只是当前行为，联机服务应当在提交阶段明确拒绝非法动作。

同等强度攻击相遇继续游戏，消耗不退；不同强度攻击通常由较强的一方胜出。防御、反制与特殊招式另有规则。

## 首批测试记录的案例

| 双方招式或状态 | 当前代码结果 |
| --- | --- |
| 双方攒 | 双方各增加 6 单位，继续 |
| Bi 对 Bi | 继续，双方各消耗 6 单位 |
| Bi 对攒 | Bi 方胜 |
| 防御对 Bi | 继续；防御方增加 2 点聂湘充能 |
| 普通防御对 Pragon | Pragon 方胜 |
| 反弹对 Bi | 反弹方胜 |
| 自杀对反弹 | 自杀方胜 |
| 双方自杀 | 平局 |
| 田立军对云 | 云方胜 |
| 三雷防对三雷 | 继续 |
| 三雷防 / Pragon防 / 沃尔沃防 / 聂湘防 对 Bi | 防御方输；部分旧说明与此不同 |

资源为零时，Bi 不可用；聂湘充能达到 4 时才可用；炸药层数决定炸药招式可用性；雷电达到 3 / 6 层时可用对应免费三雷招式。一次性招式还受使用记录影响。

## 炸药时序

第 T 回合放炸药：当回合末还未得到可用炸药层；第 T+1 回合末增加炸药层；第 T+2 回合开始时可使用。`tests/test_core.py` 记录这个时序。注意现有模拟会共用输入的列表，见 [#1](https://github.com/Kalopsiazza/DeiDei/issues/1)。

## 规则修改怎样提交

先写出具体局面：双方资源、此前相关动作、当前动作、原结果和希望得到的结果。说明是在修复程序，还是在改变玩法。维护者确认后，在独立 PR 中一并更新判定、测试和相关玩家说明。

增减招式、改变动作顺序、修改状态字段时同时检查模型兼容性。界面展示不得自行成为另一套胜负判定来源。原有 `给朋友 - 第一次玩怎么用.txt` 和 GUI 长说明保留作参考，其中的强度宣称与部分规则文字尚待复核。
