# 联机连续镜头与共享 UI 返工 PRD

日期：2026-10-02。用户已授权直接实施，无需再次审批。此文替代原联机 PRD 中独立中庭背景的实施方案。

## 问题与目标

现有 L01—L05 在切换状态时替换背景，再播放独立缩放；场景与主菜单的扑克牌大厅缺少对应关系。入口、返回、表单与身份信息又新增了另一套视觉样式。自动检查验证了操作和布局，未证明连续镜头成立。

目标：主菜单 → 联机前厅 → 创建／加入 → 房间大厅共处一个大厅。真正的背景层持续挂载，镜头位置由页面状态驱动；进入正式战局时通过毛玻璃遮蔽透视交接。联机视图使用主程序已有按钮、表单、头像、弹窗和战局规范。

## 范围与约束

- 保留 `OnlineRoom` 的网络业务、权限、错误、输入草稿、重连、时限、准备和离房行为。
- 保留共享 `BattleStage`、`SituationDialog`、`MatchResult` 与服务端 snapshot 适配。
- 不增加 UI／动效依赖，不建立新的通用组件系统，不改变规则、协议、存档和服务端计时。
- 四张 `online-atrium*` 保留原文件以便回看，但不再用于正式页面。
- 不把进入动画当作服务器暂停：最新快照持续接收，迟到的揭晓或结果以服务端为准；选卡只在正式界面且入场完成后开放。

## 持续舞台与镜头关系

| 页面 | 场景 | 镜头和内容 |
| --- | --- | --- |
| P02 主菜单 | 现有 `menu-environment` + 氛围 + 人物 | 当前构图 |
| L01 联机前厅 | 同一大厅同一 DOM | 向右侧牌廊轻推；人物退到侧后方；入口沿主菜单操作轨进入 |
| L02 房间部署 | 同一大厅 | 横移并推近左侧建筑；右侧配置、右下创建动作 |
| L03 房间接入 | 同一大厅 | 横移并推近右侧牌廊；房号、参战／观战、密码依次进入 |
| L04 房间大厅 | 同一大厅 | 镜头沿中轴继续推近；六席围绕房号就位；准备状态只改变前景 |
| L05 多人入场 | 同一舞台的擂台外围层 | 大厅先失焦，外围图在失焦峰值交接；头像在固定席位出现 |
| L06 正式战局 | 既有 `BattleStage` 与单人 `front-stage-table` | 入场扩图在虚化中淡出，正式擂台图、底层镜头、氛围和虚化直接复用单人配置；毛玻璃退去后开放操作区 |
| L07 联机结算 | 既有擂台外围层 | 擂台先进入毛玻璃，再切整场结果；最后一拍与本机突出 |
| L07 → L04／P02 | 同一持久大厅仍在后方 | 结果退场、失焦、大厅恢复清晰；沿对应路径后撤 |

只有大厅／擂台之间需要更换景别，其余路径直接动画现有背景层的 transform。不得依赖每页重启的 `from scale(1.08) to scale(1)`。

## UI 统一

- 返回：复用 `settings-back`，标签独立置顶，悬停只提亮短线和文字。
- 前厅两条入口：复用 `menu-option` 主／次动作的结构、折射和状态；按纵向操作轨排列。
- 创建／加入主动作：复用 `prepare-start`；准备、开始、复制、切换角色遵循已有 L1／L3 层级。
- 表单：使用既有设置页输入、滑杆、复选框的表现；保留原生语义和键盘行为。
- 身份：沿用主程序头像＋昵称，六席排列只负责几何；避免六个长矩形面板。
- 弹窗、卡面、资源、历史、局势回顾：复用现有实现，联机只补状态和命令。
- MOCK、连接状态、断线和操作错误保持可见；常态说明简短，不把开发过程文案放在主画面。

## 逐镜分镜

| 镜头 | 过程 | 时长与交接 |
| --- | --- | --- |
| A01 主菜单 → 前厅 | 同一环境层向牌廊平移推进；人物淡出；操作轨进入 | 镜头 950ms，内容 450ms，前后 DOM 不变 |
| A02 前厅 → 创建／加入 | 镜头从当前位置朝所选侧移动；表单淡入 | 750—950ms；返回反向，草稿保留 |
| A03 成功 → 房间大厅 | 继续沿大厅中轴推近；房号与席位依次进入 | 950ms；网络成功才触发，不做假进度 |
| A04 大厅 → 入场 | 全屏薄玻璃逐渐加强；大厅失焦后交接擂台外围层 | 1100ms；约中段更换景别，内容延迟出现 |
| A05 入场 → 正式战局 | 保留擂台外围构图，再推入正式擂台；玻璃退去 | 650—720ms；禁止选卡首帧闪现 |
| A06 战局 → 结算 | 保留最后一次公开牌桌并失焦；随后显示结果全景 | 650ms 遮蔽 + 结果清晰入场 |
| A07 结算 → 大厅／主菜单 | 结果内容退场，玻璃加强；持久大厅恢复到对应位置 | 720ms 退场 + 950ms 后撤 |

减少动态：背景保持固定，以短淡入交接；仍完整提供按钮、焦点和状态。重连和普通成员更新不重播镜头；同阶段人数变化只更新席位。

## 验收与测试

1. Electron 中记录背景节点引用，主菜单至 L04 的环境图节点始终相同，src 始终为 `menu-environment.webp`。
2. 观察开始／中间／结束帧：镜头从当前 transform 连续变化，无换图闪帧；反向返回也成立。
3. 大厅至擂台、擂台至结果与结果返回，在背景交接时玻璃模糊已可见；结果不得直接硬切。
4. 六席、2／6 人开场与正式战局在三种目标尺寸可用，主动作不裁切、关键文字可读。
5. 现有在线测试和在线 Electron smoke：草稿、错误、满员观战、准备、揭晓、结果、下一局、离房、重连和隐私断言保留。
6. 单人、欢迎流程 smoke 回归，防止共享场景和按钮受影响。
7. 新增最小转场检查：节点持续性、transform 中间值、玻璃峰值、选卡门控、减少动态与返回路径。
