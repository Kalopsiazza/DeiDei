# 第一轮详细 PRD｜规则取证、技术验证与页面探索

编号 PRD-R01 · 版本 1.0 · 作者 ChatGPT · 2026-09-11  
状态：ISSUED_FOR_VALIDATION。只授权第一轮前期工作，不授权正式游戏开发。

## 目标与玩家背景

将高中拍手游戏制作成电脑安装版，保留猜招和同时揭晓；柔和手绘牌桌为已选气质，具体页面与人物 IP 待选。朋友以 Windows 笔记本为主，Teddy 用 macOS。首版不需要手机、浏览器发布或联网注册。

本轮用事实回答三件事：原始程序到底怎样运行、选定技术能否装在两种系统并离线运行、页面信息怎样摆放可供 Teddy 选择。读档确认先于架构编写；架构先于本轮实验和出图包下发。

这里的 F01—F12 是明确的产品范围。具体算法、多人胜负和故障秒数尚未全部确定；不得把这个表当成足够编写整个游戏的正式规格。

## 第一轮 01：规则取证的详细要求

以指定输入 SHA 的源文件、规则文本、现有测试作为事实来源。逐个列出 ALL_MOVES 当前所有动作（已读版本为 31 个），保留原编号和原名。每项记录代码名、显示名、资源检查、实际扣费与收益、使用次数、延迟或状态、普通对局案例及文件定位。

每个说法标明 CODE（代码）、DOC（现有说明）、TEDDY（明确口述，附来源记录）、OPEN（尚无答案）。现有实现不等于高中最终玩法。

读取已知问题，运行现有检查。已有 expectedFailure 如实显示，不改成通过。可以在独立实验目录写取证脚本，但不能修改原始源码或增加新的正式判定。

ChatGPT 已准备的核对题：张新伟读谁的哪次记录；专属防御对 Bi；距喦与强化削资源条件；炸药时序；历强如何看实际招式；多人遇到攻击／反弹／攒同时存在时各人的结果；多人互相淘汰与整局平局。Codex 只提供现有证据和最小案例，Teddy 给出原玩法答案，ChatGPT 写入正式 PRD。

验收 RULE-01：动作目录完整且无漏项；RULE-02：每项有来源定位；RULE-03：测试如实可复查；RULE-04：多人未知未被推测填满；RULE-05：原规则、模型与正式测试不变。

## 第一轮 02：技术验证的详细要求

按 ARC-R01 1.0 的 Electron + React/TypeScript + 本机 Python 子进程候选执行。目标是能打包、打开、在本机保存一份测试档案、调用既有简单 AI 和既有双人判定，并在关闭开发服务与断网后继续操作。

实验只提供验证面板：启动信息、档案读写、固定案例、AI 返回招式、耗时和异常。不做新游戏菜单，不实现房间、不补多人算法、不画正式战斗。

先验证轻量简单 AI 路径。另用隔离环境检查现有模型能否 CPU 推理，并报告确切使用的 AI、加载路径、失败或回退。不能把自动回退后的成功算作原模型可用。a 包不要求把机器学习依赖全部塞进正式安装包；为下一包提供真实体积与打包风险。

验收 TECH-01：实际启动桌面窗口；TECH-02：关闭开发服务后的包仍可用；TECH-03：断网首次运行轻量包，不依赖已装 Python/Node；TECH-04：退出后不留 Python 子进程；TECH-05：路径含空格和中文可用；TECH-06：分别记录 Windows/macOS 的 build、launch、offline、manual；TECH-07：异常可见且不会伪装成功；TECH-08：锁定实际依赖版本并可复现。

只有一端可测时允许 PARTIAL，但跨平台总项保持未通过。Linux/Xvfb 截图不能充当 Mac 或 Windows 的运行证据。签名不足如实记录，不要求关闭操作系统的安全保护，不购买证书。

## 第一轮 03：页面布局探索的详细要求

按 UI-R01 1.0 的逐页信息清单制作。a 包出 P02 主菜单、P04 创建／加入、P05 房间、P06 双人牌桌、P07 六人牌桌、P08 观战，共六张独立布局图。每张先有简洁排布草稿，再用实际可用生图工具出一版手绘概念图；单页最多两次，超出先等 Teddy 反馈。

UI 输入包含第二张已选画风参考和原始布局白板。画风参考的猫咪、人物、口号和示意卡牌不是产品要求。不要照搬参考图错误人数；P06 自己加一人，P07 自己加五人。玩家编号不重复，不用同一头像假装多个身份。

除这些页面外，P01/P03/P09/P10/P11 的信息已由 ChatGPT 写好，出图留给后续 b 包。没有任务包不得扩展。概念图允许少量中文字瑕疵，但准确的信息摆放清单要单独提交；关键字可在后处理时排版，说明处理方式。

验收 UI-01：六张图与清单对应；UI-02：资源／倒计时位置正确；UI-03：人数与观战视角正确；UI-04：无账号登录／等级／抽卡等新增内容；UI-05：参考图来源和工具可核对；UI-06：Teddy 的具体选择另记，不能写“默认通过”。

## 当前未知，不能自行决定

正式多人结果；观众上限；房主短暂断网等待；第三次缺席在代选前还是结算后移除；出牌时长与提交后改选；房间号长度／有效期；最低系统与 Intel Mac；最终人物 IP；现有训练模型是否纳入首版安装包。

未知项影响某个实验时使用明显标记的 TEST_ONLY 常量或跳过该子项，不让假值进入正式设计。与未知无关的部分继续执行。
