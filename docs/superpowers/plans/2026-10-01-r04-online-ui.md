# R04 好友房 UI 重构 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将好友联机从通用表单和旧联机牌桌改造成「联机前厅 → 房间部署／房间接入 → 房间大厅 → 多人入场 → 正式战局 → 联机结算」的连续空间流程，并复用现有 2—6 人正式战局。

**Architecture:** `OnlineRoom` 继续唯一持有 `OnlineState` 和在线命令；`online/model.ts` 只把服务端已公开 snapshot 映射为共享 `DesktopView`，不计算规则。将当前内联在 `renderer.tsx` 的正式战局和结算视图提取为一个共享视图文件，本地单人和在线只分别提供状态、计时与动作回调；联机前厅、创建／加入和大厅仍由 `OnlineRoom` 编排，避免引入路由、状态库或第二套牌桌。

**Tech Stack:** React 19、TypeScript 7、Electron 44、原生 CSS、esbuild、Node `node:test`、Playwright Electron；不新增依赖。

**Spec:** `docs/prd/R04-ONLINE-UI-PRD.md`

## Global Constraints

- 不改变 `rooms-1.1`、`NetworkRoomPort`、preload 白名单、规则、存档、房间号、密码、超时、掉线或房主离房语义。
- 创建只提交 `password`、`turn_ms`、`early_reveal`、`spectator_cap`；加入只提交 `room_code`、`password`、`role`。
- 未揭晓前不得渲染其他玩家招式；观众和已淘汰玩家不得获得选牌操作区。
- scripted fixture 必须始终显示 `MOCK`，且不能被称为真实联网验收。
- 正式战局只有一套 `.battle-table`；删除旧 `.online-table`，不保留备用实现。
- 只使用 React、原生 CSS 与现有工具；动效只动画 `transform`、`opacity` 和毛玻璃强度。
- `prefers-reduced-motion` 使用 120—180ms 淡入淡出，不依赖镜头位移表达状态。
- 1000×650、1366×768、1920×1080 都不能裁切主动作、产生横向溢出或让关键文字重叠。
- 当前 worktree 已有未提交工作；只暂存任务列出的文件，不覆盖或清理其他改动，不 push、merge、tag 或发布。

## Review Focus

- 其他玩家未揭晓招式和 resume token／密码：任何前厅、重连、选牌和观战 DOM 都不得出现这些私密值；Task 1 与 Task 5 固定测试。
- 长房间号、20 字昵称和 6 人满席：三个目标窗口宽度均保持可读且无溢出；Task 4 与 Task 7 固定测试。
- pending、重连和迟到旧 snapshot：保留已填内容与已公开画面、锁定冲突命令，旧房间不能复活；Task 3 与 Task 5 固定测试。
- 首帧和减少动态：多人入场完成前不闪现手牌，减少动态仍可完整操作；Task 6 与 Task 7 固定测试。
- 房主／普通成员／观众／已淘汰四种身份：按钮、结算去向和下一局行为必须分别正确；Task 4、Task 5 与 Task 6 固定测试。
