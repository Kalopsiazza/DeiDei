# DeiDei 游戏设计讨论

更新日期：2026-09-11  
记录版本：0.1  
用途：持续记录游戏方向与讨论进展，供 Teddy 和协作者接续使用。

> 这是设计讨论记录。以下区分「Teddy 已确认」「当前倾向」和「助手提案／待讨论」。记录上传不表示其中的提案已获确认，也不表示功能已经开发。当前以大方向为主，具体招式判定留到后续开发时讨论。

## 当前方向

以 Teddy 的牌桌草图为第一版主要方向：下方卡牌选招，中间呈现本轮交锋，其他玩家围绕中央区域。保留同时选择、共同揭晓以及朋友之间猜招的体验。

本次明确采用的操作方向不包含自由移动、走位或瞄准。2D、2.5D、3D 仍属于可讨论的美术表现选择，采用立体画面不自动引入移动玩法。卡牌作为招式载体，也不自动引入随机抽牌、组牌和收集系统。

项目来自高中课间拍手游戏；Teddy 表示，熟悉手势后，线下一回合约一秒。线上希望保留连续感，不把一秒设为已经确认的出牌时限。原始程序和 AI 来自同学的机器学习作业，Teddy 已说明获得继续开发的授权。本记录不替换仓库的来源与许可文件。

## Teddy 已确认的交互与玩法方向

### 牌桌布局

- 下方：自己的卡牌与操作区域。
- 自己的资源：跟着卡牌走，放在卡牌附近；不继续远放在顶部。
- 卡牌区域上方：明显的倒计时进度条，显示本轮剩余出牌时间。
- 中央：本轮卡牌交锋、角色动作与特效的共同展示区域。
- 周围：其他玩家所在位置。草图中的四个位置仅作布局示意，最大人数尚未确定。
- 左下角：自己的人物形象与快捷发言入口。
- 菜单与状态提示：容纳其他功能。AI 托管是草图里举出的候选功能，尚未确定首版提供。

其他玩家的资源贴近其头像，是助手已提出的布局建议；具体展示多少信息尚待设计。

### 多人默认对全场出招

Teddy 澄清：目前一般招式作用于其他所有玩家，无需先选择某个攻击对象。例如，甲出 Bi，乙出 DeiDei（攒资源），即使其他玩家出了其他招式，乙也会因这一攻击出局。

这一例子确认的是 Bi 对正在攒资源者的作用，不据此推定甲或其他所有玩家的最终结果。多人更复杂的组合以后再讨论。

当前不提供常规目标选择步骤。只有将来明确加入仅作用于一个人的招式，才重新考虑选目标。此前助手提出的「点卡片后再点目标」「将卡片拖向目标」不再作为当前方案。

### 出牌与揭晓节奏

双方或多人在同一轮内选择招式，再共同揭晓。Teddy 认可避免无意义等待，以及在卡牌上方清楚展示倒计时。

当前倾向：倒计时表示最长等待时间，全员完成出牌后可以提前进入揭晓。具体时长、怎样表示最终提交、是否允许提交后改选、超时默认行为尚未确定。

揭晓前不向其他玩家透露本轮的牌。准备状态和选了什么牌分别处理。当前记录不指定确认按钮、长按、拖动或快捷键方案。

### 演出可以有主次

Teddy 提出：动画不能所有招式一概而论；攻击、挡住攻击、反弹等应当有易懂的先后关系。

Teddy 特别提出的案例：当自己出大 Bi（花费 5 个 DD），其余玩家的小牌都无法应对、这一轮确实将被淘汰时，可以让大 Bi 获得完整的帅气演出，其他人的完整出招动画停下或省去。

这一主次思路已明确；怎样保留所有人的出牌信息、怎样显示其他有效结果，是下节的助手提案。

## 中央演出：助手提案，待 Teddy 讨论

### 一轮交锋由实际结果安排重点

先知道这一轮发生了什么，再安排镜头与动作。所有人同时亮牌，不要求所有人的完整动画同时播放；同一张牌也不必每次使用完全相同的镜头。

建议采用三种篇幅：普通攒资源与普通抵消用短反馈；一般交锋呈现攻击与响应；决定淘汰或整局胜负的时刻才给重点演出。不要每轮为每个人分别播放一套完整动作。

出牌图标可以保留在各自头像附近，让玩家知道每个人出了什么。被省去的是冗长的演出，不是本轮的行为记录。

### 几种局面的演出草案

| 局面 | 建议怎样表现 | 希望玩家看懂什么 |
| --- | --- | --- |
| 一个 Bi 作用于其他玩家 | 出招者做一次短动作；共享场地出现带有来源标记的扩散冲击或分开的光束；其余席位各自出现挡住、反制或被击中的反馈 | 一次招式能触及多名玩家，各人的应对可以不同；不用角色挨个跑去攻击 |
| 攻击遇到普通防御 | 亮牌时可以先出现防御姿势或淡盾；攻击抵达时再播放挡住、震动、破碎等对应反馈 | 事先选了防御，命中瞬间才体现防御是否奏效 |
| 攻击被反弹 | 攻击发出，反弹者附近出现镜面或翻转符号；对应能量转向回到攻击来源；结果落在受到反制者身上 | 攻击从谁来、为何返回、谁因此出局；其他席位有自己的本轮反馈 |
| 自 Bi 遇到反弹，按 Teddy 的例子由反弹者出局 | 给这一组合专门的漫画式「反噬」桥段：自 Bi 方做夸张的自指动作，反弹方的镜像跟着模仿，镜面随即故障，反弹方被弹飞；保留双方牌名，并短暂提示「自 Bi 克制反弹」 | 看懂这个组合的反转；不画真实自伤，也不虚构自 Bi 方先死亡再复活的过程 |
| 大 Bi 对全体无法应对的小牌 | 所有牌一起揭晓，小牌保留图标或短前摇；大 Bi 获得镜头重点，随后显示实际淘汰结果，其余完整攻击镜头可省去 | 强招获得表现空间，仍知道其他人出了什么 |
| 大招遭到能改变结果的回应 | 先让大招制造期待，再把重点交给真正奏效的回应；不能仅凭 DD 数值决定谁获得最后镜头 | 反转本身也值得帅气演出 |

这些是表现提案，不是新增招式规则。扩散波、镜面、反噬等造型仍可随美术方向改变。

### 保留结果，不让动画偷偷改变玩法

镜头先后不赋予招式新的先手权。小牌动画没完整播放，不代表这张牌被取消、没花资源，或无法产生它原本应有的效果。

若一个看起来较小的动作仍导致别人出局、形成重要反制或改变重要资源，应保留可见反馈。若同一轮存在多条重要交锋，可以分别在有关席位短暂表现，不为某位「主角」隐藏其他有效结果。

允许准备动作共同出现；攻击命中后再出现受击与防御反应。更适合强调因果的环节可以分先后，避免把所有盾、弹道、出局效果毫无区别地堆到同一瞬间。

## 美术：下一项讨论，尚未确认风格

Teddy 已提出接下来讨论美术，但尚未选择具体画风、角色外形或制作方式。白板草图用于表达布局，不能据此认定成品采用手绘风。其他项目的美术偏好也不自动用于 DeiDei。

助手当前更倾向轻松、夸张、带漫画感的小剧场。这样的方向便于把手势、人名招式和出人意料的克制做成好懂的短桥段。严肃写实并非被禁止，只是需要另行解决这些桥段的表达。

| 候选气质 | 卡牌与场景可以怎样做 | 人物与演出可以怎样做 |
| --- | --- | --- |
| 课间涂鸦漫画 | 有节制的纸张感、彩笔线条、招式贴纸，清楚的牌名与资源显示 | 原创夸张小人、手势、速度线和少量文字特效；校园情怀自然进入画面 |
| 玩具擂台 | 小型立体桌面或舞台，简洁卡牌，清楚的玩家席位 | 玩偶比例、弹性动作、镜面与冲击波；可以采用 2.5D 或 3D |
| 明快漫画竞技场 | 干净背景、较醒目的色块、竞技徽章式卡面 | 强动作轮廓、关键反制特写、短暂漫画定格；更强调对决的帅气 |

下一步适合讨论玩家看到它时希望感到「像课间一起胡闹」还是「像一场帅气对决」，以及两者各占多少。随后再选择人物、卡面、场景与 2D／3D 的具体组合。

当前不指定游戏引擎、不下发素材制作任务、不认定任何画风已获批准。拍手和原有手势值得作为动作与声音候选保留，是否采用仍待讨论。
