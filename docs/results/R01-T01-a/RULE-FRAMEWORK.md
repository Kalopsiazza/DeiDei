## 1. 基础概念与分类

### 1.1 一次出招的几个不同层面

| 层面 | 表达什么 | 例子 |
| --- | --- | --- |
| 提交入口 | 玩家提交的卡牌/入口，旧编号保持、新入口另列 | 张新伟、雷电·三雷、普通三雷 |
| 实际招式 | 来源解析后，本人这一回合使用的完整原招 | 张新伟复制旋转三雷，实际招式仍是旋转三雷 |
| 获取来源 | 本次招式怎样产生 | 普通、炸药、雷电、张新伟；决定明确关联的费用/收益例外 |
| 选定分支 | 本轮唯一使用的互斥效果 | 旋转三雷取三雷或自 bi；不改变完整原招身份 |
| 条件状态 | 根据局面算出的成功/未成功 | 自 bi、历强；不是玩家再选一次招 |
| 属性与作用 | 这个招在何阶段能做什么、对谁做了什么 | 防御100；P2接住攻击；P3对原攻击者回击2 |

张新伟、复合招的分支、反弹生成的回击、针对田利军的代码杀，都不能被误记为一个玩家同时提交了多个招式。张新伟是特殊替身入口，不需要伪造一份张新伟自己的攻击/防御数；先解析原招，再获得原招阶段属性。

### 1.2 目录分类

| 主分类 | 成员 | 分类含义 |
| --- | --- | --- |
| 普通攻击 | bi、三雷、大bi、削、Pragon、沃尔沃 | 产生原始攻击，具有用于P2对撞的等效防御；具体数值与特别匹配见逐招条目 |
| 特殊攻击 | 小贝、扇贝、聂湘 | 攻击之外还有特别抵消、穿防或资源资格；不按数字自动取消例外 |
| 防御/附加状态 | 普通防御、四种专属防御、距喦、田利军 | 防御数、比较符、匹配条件和有效阶段分别记录 |
| 反制/吸收 | 反弹、吸收、云 | 防御、回击、资源收益和阻止攒分开表达；对田利军另有代码杀匹配 |
| 条件成功 | 自 bi、历强 | P1生成成功状态；其攻击对象及持续保护依条件决定 |

| 资源 | 攒、炸药 | 即时增长、增长被阻止、延迟成熟等不同效果 |

| 来源入口 | 张新伟、3种炸药攻击入口、2种雷电攻击入口 | 解析为完整实际招式，继承该招阶段效果，使用自己的来源成本 |

主分类用于阅读，每招可有多个角色。第35轮将高阶资格统一改为攻击强度≥2，由强度派生，不再维护一份独立高阶名单；费用、防御和击杀数不能代替攻击强度。

### 1.3 单位与高阶资格

攻击/防御数值、DD余额、实际费用、可吸收DD分别存放。反弹/吸收防御100、自 bi/历强伤害10000，并不等于消耗或获得同额DD。分数写1/3、1/2、7/2，无穷写明确的POSITIVE_INFINITY；旧引擎1DD=6内部单位只作为转换依据，本次未修改单位。

**当前高阶定义：攻击强度≥2。** 曾义攻击0，不属于高阶、不能成为张新伟复制目标；大bi攻击5，普通及曾义赠送来源都满足门槛。不再要求逐个批准或维护高阶名单。旧代码deidei_env.py:84—90仍使用固定集合，只作为旧实现证据保留，本次未改引擎。

高阶门槛与复制许可共同决定“这次出招是否更新复制记录”，记录内容仍是完整实际原招。免费大bi到账本身不是出招，只有实际使用后才形成这次BigBi历史；来源不影响5≥2的判断。曾义会清空原有效最近高阶资格；同局完整历史可保留，但不能回填复制资格。新开一局则按G58清空全部规则历史。

**复制资格还有明确例外：自bi、历强、反弹不能复制。** 成功自bi/历强的攻击10000达到高阶数字门槛，但复制禁用仍生效；失败状态攻击0，本来也不到门槛。反弹是否产生高值回击不影响其禁用。规则因此分成“强度分级”和“是否允许复制”两层，不需要恢复完整高阶名单。

按已定属性与完整原招规则提炼，复合招用本轮选定分支的攻击属性判断≥2，但记录仍是RotateThree/FlipVolvo。选到自bi分支不等于本人的完整实际招式变成Suicide，张新伟仍复制完整复合招并重新选分支；不直接复制历史成功状态。第35轮用“三雷后成功自bi仍复制三雷”确认自bi不覆盖旧记录。因此记录只保存最近可复制高阶完整原招；禁用招和不满足门槛的招式不覆盖，曾义按明确例外清空。第38轮新局规则加入后，成功自bi造成淘汰会触发重开或结束，不能在实际下一局沿用旧三雷记录；H05仅保留为记录更新的局部示例，完整推进见E06。

本次取证目录原样保留31项旧动作索引、枚举值。选牌区按合法性排序与运行时动作标识分开。用户最新决定新游戏从零开发、AI专项后置且可临时接入旧AI，因此legacy映射只作溯源，不要求新产品沿用旧动作编号、状态编码或模型动作顺序。新增曾义与“曾义赠送·大bi”来源入口只放在new_entries讨论区，legacy_index/legacy_enum为空；未给旧模型或引擎增加动作编号。NoMove为旧保留状态，不是新增招式；显示名统一写自 bi、田利军，底层Suicide/TianLiJun标识保持。

## 3. 四阶段判定

| 阶段 | 读取与生成 | 可以登记什么 | 不能提前做什么 |
| --- | --- | --- | --- |
| P1 PREPARE 准备 | 回合开始状态、合法提交、来源、次数/历史、候选分支；锁定后生成本轮属性 | 资格、计划支出、实际身份、唯一分支、条件成功、属性及有效阶段 | 不因试算扣真实资源，不提前淘汰或更新历史 |
| P2 PRIMARY 原始作用 | 全场已生成属性、原始攻击及资源作用规则 | 防御结果、原始致命作用、特殊代码杀、吸收收益、攒被阻止、待执行回击 | 不立刻执行回击，不移除受到致命作用的参与者 |
| P3 RETURN 回击 | P2登记的逐条回击与本阶段可用防御 | 原值回击结果、致命作用和归因 | 不重选分支、不重新判断自 bi/历强成功，不恢复过期对撞防御 |
| P4 COMMIT 汇总 | 所有阶段作用记录、一次费用及状态更新规则 | 本轮完整淘汰/击杀/资源/历史/成熟记录，随后交G57判断继续、重开或终局 | 不按事件先后抢击杀，不重复执行相同来袭收益或入口/原招成本 |

P2也登记G31/G37的直接淘汰，代码杀没有伤害值，不用10000或正无穷取代。仅按明确条件匹配：田利军遇三种反制、小贝遇攒；不扩成通用必杀。P1完成实际招式及条件效果解析后确定匹配，P2登记、P4淘汰。

P2包含自 bi/历强的条件伤害。它们不会被挪到“防御都消失之后”从而绕过10000与防御的比较。P4按明确资源规则合并：吸收/云取消攒者本次增长，田利军清空则覆盖该攒者最终DD为0；其它吸收者的独立收益照常记录，不因目标清空或作用者本轮死亡而撤销。不能用玩家遍历顺序决定覆盖关系。

**分支试算**：P1先固定选择者集合。对某人的一个候选，只保留本人和固定招式玩家，生成该局部候选属性并执行P2—P4的无副作用试算；不递归进入选分支。必须算完回击再评价存活/击杀；读取本轮淘汰/击杀集合，不使用重开后的空状态评分，试算不实际推进整场或取消延迟。选完全部人的唯一分支后，重新由全场生成正式属性并结算一次。试算排除者在正式回合恢复，用户已接受此风险。

**阶段内顺序**：每阶段各条普通作用读取同一份已确定输入，先收集结果再合并；改变状态的特殊效果必须明确阶段，不偷偷借玩家编号排序。中间的致命记录不改变本轮参与名单。

## 4. 数据结构与字段职责

这是一份可审阅的数据设计。MOVE-CATALOG.json使用事实包装value/status/evidence，目的是防止旧代码候选混入确认规则；它不是游戏应永久使用的解释器格式，也不能直接加载它运行对局。

### 4.1 招式定义

| 字段 | 用途 |
| --- | --- |
| id / legacy_index / legacy_enum / name | 本目录保留旧动作溯源映射，显示名独立；新产品动作ID/编码另由正式架构确定 |
| category / roles | 主分类及多重职责，不用一个等级代替全部规则 |
| resolution | P1如何得到实际原招、来源或唯一分支；入口可引用原招，张新伟无需伪造自身攻防 |
| availability.evaluate_in / rule | P1持有条件、次数与资格 |
| cost.computed_in / commit_in / rule | P1计算一次费用，P4应用一次；来源覆盖原招费用 |
| high_record | 强度≥2并满足复制禁用规则的派生说明；高阶数值与可复制性分开，非逐招手动高阶名单；禁用招不覆盖旧复制记录，见G51 |
| attributes[].value / comparison / match / when | 属性数值、比较符、匹配范围与条件；match同时记录明确允许/禁止的特殊匹配，不能只用数值替代 |
| attributes[].generated_in | 属性或其动态规则在哪一阶段形成；反弹回击值在P2按来袭产生 |
| attributes[].active_in.PRIMARY / RETURN | 在P2/P3是否有效。true/false分别明确有效/无效，null明确尚待定；这属于防御适用范围，不是has_defense |
| effects[].evaluate_in / resolve_in / commit_in | 何阶段判断条件、何阶段产生作用、何阶段写回状态；纯判断没有状态写回 |
| effects[].kind | 特殊直接淘汰明确标DIRECT_ELIMINATION，不需要伪造attack/damage字段；其余效果仍按已有规则表达，不新增通用效果引擎 |
| effects[].rule | 读取对象、触发条件、目标、结果及来源说明；条件不成立不生成对应效果 |
| common_commit | 引用共同的一次支出/历史/炸药队列更新，不为各张卡复制一套结算 |

分支或来源引用继承原招效果/攻防，不能覆盖已确定的实际身份、入口资格和成本；原招效果中的资源支出也必须引用同一来源费用。例如复制聂湘不执行普通扣4充能。反弹只继承该次攻击数值，不自动复制完整招式、buff、来源或特殊效果。反弹本身明确禁止成为张新伟复制目标，不用回击值绕过禁用。

大bi说明“数值”和“匹配”必须分开：普通防御对大bi明确允许，不能先用通用阈值1把它排除；反弹对大bi明确禁止，不能因5≤100就放行。已有match与effects.rule足以记录这两个特殊匹配，P1随招式形成规则、P2逐来袭判定；不额外提高普通防御的通用数值，也不改变大bi实际身份或攻击强度5。匹配结果记录命中的G42及具体原因。这里仅落实已明确两项，待定范围冲突不靠任意遍历顺序决定。

### 4.2 回合中需要的记录

| 记录 | 至少包含什么 | 生命周期 |
| --- | --- | --- |
| 玩家状态 | DD、雷电、炸药层/延迟队列、聂湘充能、buff、相关次数、上一实际招式、最近可复制高阶完整原招（可为空）、是否在场 | P1读取，P4生成下一状态 |
| 本轮动作 | 原始提交、实际招式、来源、唯一分支（如有）、条件状态（如有）、计划费用和阶段属性 | 本轮固定；普通招无需成功/失败或分支字段 |
| 作用记录 | 作用者、目标、类型、阶段、适用时的数值/资源变化、触发依据、防御/反制结果、致命原因；直接淘汰记录类型DIRECT_ELIMINATION，不填伤害值 | P2/P3产生；P4汇总。反弹引用原来袭，作用者为反弹者 |
| 回合结果 | 本轮完整下一状态、淘汰集合、每人有效击杀集合及依据；另给出同局继续/新局/唯一存活者获胜/全员淘汰无人获胜的推进结果 | 先完整结算一次，再按G57/G58推进，不用新局初始值覆盖本轮作用日志 |

“死亡不算属性”指本轮的淘汰结论不写入招式属性，不触发本轮招式重算或取消后续作用。玩家状态仍需记录是否在场，用于决定下一回合参与者；这与招式的成功/失败状态不同。P2/P3只累积致命依据，P4才提交淘汰。

每项代码杀只在被克制招式条目定义一次：田利军条目由反弹/吸收/云触发，小贝条目由攒触发。对应反制者/攒者为作用者，被克制者为目标；引用方不重复登记。按G16推导：多个对手各自匹配，各记独立有效击杀，目标只淘汰一次。代码杀归因不改变普通攻击值。

两贝互相抵消、小贝对攒攻击不生效，属于P2的逐目标攻击匹配结果；记录作用者/目标、未生效原因及规则ID，保留该招攻击数值与对其他人的攻击。不能先把整招攻击设为0，也不能因为P2记录了代码杀就提前删掉小贝玩家。

G21未成功且回合开始DD=0的历强既然按攒处理，按该通则推导也采用攒对小贝的匹配，但实际原招仍为历强，供G19历史比较使用；未成功且DD>0以及成功历强均不走攒分支。

同一玩家可在P2登记多次吸收或多条回击，但仍是一招、一次费用、一次历史。不同玩家的相同招式属于不同来袭；同一条来袭不能重复收益。

### 4.3 跨阶段例子

- 反弹：P1生成≤100防御和反弹规则；P2逐来袭筛选并产生原值回击；P3仅回原攻击者；P4汇总击杀，来源为反弹者。P2受到自 bi致命作用不取消合规的其它回击。

### 4.6 回合、每局与整场的推进

- **回合**：一次同时出招，完整执行P1—P4。
- **一局**：本次参战者从初始状态开始，连续进行无淘汰的回合；出现淘汰后按下表结束本局或整场。
- **整场**：连续淘汰、由存活者开新局，直到产生唯一存活的赢家，或全员淘汰、无人获胜而结束。已淘汰者不会因新局重新加入。

| P4完成后的情况 | 推进结果 |
| --- | --- |
| 无人淘汰 | 保留本轮得到的状态，继续当前局下一回合 |
| 有人淘汰，仍有至少2人存活 | 只由存活者开始新局；局内回合从头计，全部玩法状态恢复初始值 |
| 剩1人 | 该玩家获胜，结束本场，不创建只有1人的新局 |
| 剩0人 | 全员淘汰，无人获胜，本场结束；获胜者为空，不复活本轮玩家继续重开 |

“每局一次”和“首次免费”都以新开的一局为界；不是整场只能一次。重置对象是存活者的玩法状态：包括DD/充能/buff、lastMove/最近可复制高阶、云/田利军/张新伟/历强/曾义等次数，炸药全部库存与进度，曾义状态与到期轮次、已获得但未用的免费大bi。曾义重置为unused、奖励到期为空；旧局的休整和等待任务不带入新局。单次曾义施放的G44保留不利计数，而对局重开的G58全部恢复初始，两种清空不得混用。

最少在对局层区分当前参战者、局编号与局内回合编号；规则状态以本局初始值创建。身份与本场淘汰结果保留，用于只让存活者入场。实现上可归档旧局的完整结算记录，但新局不得读取旧局记录来触发历强、复制高阶、恢复炸药或领取曾义奖励。

先计算旧局本轮全部作用与资源，再产生对局推进结果；不得因第一个人死亡就立刻清空其它人的状态。本轮收益和击杀仍能在该轮日志中解释，新局状态则从初始值开始。所有T+1/T+4等延迟按本局回合推进；新局取消旧局尚未完成的延迟过程。
