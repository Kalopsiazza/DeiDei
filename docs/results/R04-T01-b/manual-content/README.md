## 内容约定

- `entry_id`、`doc_id`、招式名称与三类主分类沿用现有 catalog。标签用于跨分类查找，不改变实际攻防。
- `costs` 分开记录持有条件与实际支出；`qualification` 保留原资格文字。DD 使用精确分数字符串，资源数量不从描述中解析。
- `combat_modes` 分状态展示攻击与防御。`value` 是属性强度，不是 DD 费用；`comparison` 区分等值和上限；`match` 区分普通防御、专属类别、对撞、反制或复制；`scope` 与 `note` 必须一起显示。
- `beginner` 是首层说明：一句作用、关键风险、当前术语、最多三张后续牌和最多三个首选示例。完整 `example_ids` 供展开查阅。费用、门槛和关键风险始终可见；全部精确信息继续可展开，不以入门路线限制实际出牌。
- `effects`、`cautions` 完整保留，可展开查阅。反弹回击有独立字段；复合招、强化削、炸药次数与条件成功失败分别有状态，禁止把多个分支数值相加。
- `relations` 是有方向、有条件的关联入口，包含目标、关系说明和依据；不宣称穷尽对局，也不生成无条件的强弱排行。
- `rule_ids` 连接既有 R01—R28 原条款。显示条款标题、按主题阅读，原文继续可追溯。文案整理不回写底层规则、引擎或旧玩家指南。
- `tip` 提醒容易误读的地方，不许写必胜承诺。`easter_egg` 是原创趣味便签，不是人物真实语录；默认隐藏，悬停、键盘聚焦、轻触均可揭示，必要规则不能藏进去。
- `chapters` 整理通用规则，供关联规则、入门路线与搜索使用。图鉴静态属性不携带 fixture 的 `available`，也不把开发预览资格当永久资格。
- `onboarding` 从攒、bi、普通防御开始，按步骤提供文案、问题和答案；`questions` 是预设常见问题入口，不承诺自然语言搜索；`glossary` 只在当前需要时解释。
- 场景首层使用 `scene_label` 短标题并按当前卡牌编号；`context_copy` 只保留上一招、复制记录等未在资源区展示的必要背景。原 `title`／`setup_copy` 保留为校对资料，界面不再直接展示。
- `examples` 使用现有 wire 状态与招式编号，固定两人条件，包含人工写定的期望账目；由现有 `new_match`／`resolve_round` 核对。状态资源沿用核心字符串编码，`dd6` 是 DD 的六分之一单位，显示使用既有 `ddText`。休整由系统补动作，示例不得伪装成实时对局或多人结论。`playback` 是核心结果的静态呈现字段，记录前后资源、等待炸药数量、实际动作与攻击／回击／直接淘汰事件；renderer 只播放，不另算判定。
- `creative_brief` 包含入口／栏目／按钮文案、四段演出分镜、四个互动创意与试玩验收目标；`presentation` 说明首层数量限制和统一 UI 的方向。当前已实现通知式连续层叠卡牌／图标网格、固定档案、通栏双层内容切换、单行横向场景浏览、问题入口、预设示例、原条款跳转、关联返回与便签揭示；策划中更细的演出仍可在试玩后调整。

## 当前接入

`game/desktop/ManualArchive.tsx` 直接引用本 JSON，由 esbuild 打进既有 renderer；没有增加文件访问权限或运行时服务。左侧连续滚动的层叠卡牌列表、右侧持续档案，加搜索直接定位和攻击／防御／技能分类。背景镜头推进、返回按钮、玻璃与焦点状态复用设置页规范。右侧先读作用、费用与关键风险，再看预设例子、精确属性、时序和关联内容；彩蛋只占一个不干扰阅读的小入口。
