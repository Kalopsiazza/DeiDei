# DeiDei 桌面端设计标准

状态：R04-T01-b 桌面界面统一规范，2026-09-30 起作为当前前端视觉真源。

## 1. 目的与边界

- 产品：朋友之间玩的二次元战术卡牌游戏，不是网站、数据后台或通用桌面工具。
- 第一印象：红黑动态海报、冰青折射、轻薄玻璃、清楚的战术层级。
- 主要玩家：第一次打开游戏的本地玩家，以及邀请朋友进入房间的玩家。
- 本轮覆盖：加载、初次档案、主菜单、单人准备、本地正式牌桌、好友房入口和大厅、结算、设置、经典规则图鉴、弹窗及错误状态。
- 本轮排除：好友房正式对战态。它继续保留现状，等待独立任务重新设计。
- 行为边界：不改变规则、招式语义、联机协议、存档、worker、CSP、Electron 权限或 TLS。

## 2. 设计读法

- 模式：在现有 DeiDei 品牌上的视觉重构，保留信息架构和真实操作。
- `DESIGN_VARIANCE: 8`：非对称海报构图，避免页面都变成居中卡片。
- `MOTION_INTENSITY: 7`：有镜头推进、分层切换和明确反馈，不做无目的循环特效。
- `VISUAL_DENSITY: 6`：菜单留白，图鉴和大厅承载更多信息，但仍保留清楚的主次。
- 技术：React 19 加原生 CSS。没有运行时 UI、图标或动画依赖。

## 3. 视觉身份

### 色彩

| 角色 | 值 | 用法 |
| --- | --- | --- |
| 夜色底 | `#080b10` | 页面深色底与遮罩 |
| 炭黑 | `#121922` | 次级表面 |
| 主红 | `#ef3f56` | 唯一主强调色、主动作、攻击 |
| 暗红 | `#8f1e31` | 红色阴影与按下态 |
| 冰青 | `#83e6f1` | 信息折射、焦点、技能与联机 |
| 主文字 | `#f7f4ed` | 标题与关键标签 |
| 次文字 | `#a9b3bd` | 说明、元信息 |

- 红色只表达主动作、危险或攻击能量。
- 冰青只表达焦点、联机、技能和玻璃折射。
- 禁止新的紫蓝渐变、纯黑大块、纯白大块和多套强调色竞争。

### 字体

- 使用系统无衬线字体，不新增字体文件。
- 展示标题：紧凑、粗体、负字距，可压在人物后方。
- 页面标题：36-64px，最多两行。
- 正文：13-16px，行高 1.6-1.8。
- 元信息：9-12px，只用于真实状态、分类和快捷提示。
- 中文为主，英文只作为短标签，不用无意义版本戳和装饰句。

### 形状

- 主动作：硬边斜切，圆角为 0-2px。
- 表面与弹窗：硬边矩形，最多 2px 圆角，依靠折射边而非圆润卡片表达层级。
- 头像保留现有纸绘外形，作为唯一可明显柔和的元素。
- 不使用通用胶囊按钮、三张等宽网页卡片和大面积实色面板。

## 4. 背景与玻璃

### 分层舞台

合成顺序：环境图、缓慢光晕、标题、氛围碎片、人物、真实 UI。人物可以穿过标题，但不得盖住按钮和正文。

- 主菜单：环境完整可见，人物为第一视觉焦点。
- 二级页：环境轻微推进或偏移；页面内容接替人物成为信息焦点。
- 同一张环境图可复用，但每页用裁切、位置、光区和内容结构形成不同场景。
- 背景缺失时使用红黑 CSS 渐变，交互仍必须完整。

### 整屏薄玻璃

- 设置页玻璃属于整屏背景层，不是右侧一块黑面板。
- 玻璃从右向左渐隐：右侧折射最清楚，越向左越透明，左侧背景与人物保持可见。
- 环境图本身先做 3px-5px 景深失焦，再叠加 `blur(18px-24px) saturate(112%-125%)` 的渐隐折射；模糊必须肉眼可见，背景色总透明度不高于 12%。
- 内容镜片只增加细边、内高光与局部阴影，不重新铺一层大色块。
- `prefers-reduced-transparency` 下使用高对比实体深色，保证文字可读。

## 5. 布局骨架

- 页面安全边距：桌面 42-84px，窄屏 22-32px。
- 主验收尺寸：1366x768；兼容 1000x650 和 1920x1080。
- 非对战二级页优先使用一主一辅的非对称结构，不复用同一张居中纸卡。
- 主要动作必须在首屏可见。
- 小于 820px 时改为单列，先信息后装饰；装饰层可降低透明度或隐藏。

## 6. 按钮层级

### L1 主动作

用途：开始对局、创建房间、保存并关闭、再来一场。

- 外观：主红斜切或红色能量边，最少 48px 高；一个页面同一时刻只出现一个最强主动作。
- 悬停：向操作方向位移 2-6px，文字下方扫过一次高光，边缘短暂点亮。
- 按下：回缩 1-2px 或缩放到 0.98。
- 焦点：冰青双层轮廓，不依赖颜色变化。
- 禁用：保留文字和轮廓可读性，不仅降低透明度。

### L2 场景动作

用途：好友联机、加入房间、确认设置分类中的主要选择。

- 外观：炭黑透明切片，冰青细边和轻微内折射。
- 悬停：短距离抬升或横移，局部高光，不整块变白。
- 动效时长：160-220ms。

### L3 工具动作

用途：返回、关闭、搜索辅助、复制房号、设置、规则入口。

- 外观：透明底、文字、细分隔线或单侧导轨。
- 悬停：文字和细线提亮，位移不超过 4px。
- 不使用主动作的红色填充、扫光、外发光或大面积底纹。

### L4 危险动作

用途：退出游戏、离开房间、放弃修改、重建档案。

- 默认：低调红色描边或文字，不与 L1 同时争夺视觉焦点。
- 触发不可逆结果前使用确认弹窗。
- 确认按钮明确写出结果，如“确认退出房间”，不使用模糊的“确定”。

### L5 图标动作

用途：关闭、卡牌详情、资源详情。

- 最小点击区 36x36px，图形居中。
- 默认透明，悬停只出现局部折射底与焦点轮廓。
- 不将字符颜色与背景同时提亮，任何状态都必须看清标签或图形。

### 通用状态

- 默认、悬停、按下、键盘焦点、禁用、忙碌必须齐全。
- 高光永远位于文字下方，按钮文字在独立上层。
- 桌面按钮标签保持单行。
- `prefers-reduced-motion` 下取消位移、扫光和错峰，仅保留颜色、边线和焦点。

## 7. 页面组件

### 导航与分类

- 当前项使用单侧导轨、清晰白字和短距离位移。
- 悬停和选中强调放在前景文字、导轨与短线，不在文字背后铺白色或大面积高亮底。
- 未选项降低层级，但文字对比度不低于正文标准。
- 分类切换用 220-380ms 的淡入加 8-18px 位移，表达内容已替换。

### 表面与信息块

- 只有真实层级需要承载面时才使用玻璃或边框。
- 多项信息优先用留白、分组、大小和线性导轨，不把每段文字装进卡片。
- 同页最多一个主玻璃表面；其余区域使用透明底或局部折射。

### 表单

- 标签位于输入上方，帮助文字位于输入下方。
- 输入使用深色透明镜片、明亮文字和冰青焦点边。
- 错误就近显示，保存失败不得覆盖输入。
- 滑杆、复选框、头像选择都提供 hover、active、focus 和 disabled 状态。

### 弹窗

- 背景：低透明黑色加 8-12px 模糊，仍看得到所在场景。
- 容器：深色薄玻璃，顶部一条冰青折射边，左下可带一条短红色能量边。
- 标题和关闭动作分层清楚，正文不超过约 65 个汉字宽。
- 操作从低到高排列：取消、次级、主确认；危险确认使用明确红色语义。
- 打开：淡入加 12px 上移，220ms；关闭由原生 dialog 完成，不增加复杂退场状态。

### 错误与空状态

- 错误条使用暗红透明底和高对比文字，保留重试或返回动作。
- 空状态说明“为什么为空”和“下一步能做什么”，不只显示一个图标。
- 加载使用与页面结构一致的光带或短文案，不使用无意义转圈。

## 8. 招式图标标准

- 数量：catalog 中 33 个招式一一对应，文件名使用 `entry_id`。
- 文件：透明 PNG，项目路径 `assets/moves/<entry_id>.png`。
- 构图：正方形、单一中心符号、外轮廓清楚、四周留 12%-18% 安全区。
- 颜色：每枚最多 3 个主色。攻击以红为主，防御以冰青为主，技能以白加红青组合。
- 质感：二次元战术卡牌的半绘制图标，硬边、高光和少量粒子，不绘制完整场景或人物。
- 禁止：文字、数字、品牌、复杂背景、细碎线条、相似度过高的重复轮廓。
- 缩小验收：在 48px 能直接区分，在 28px 仍能通过轮廓和主色识别。
- 图鉴和本地正式牌桌都使用同一套正式图标；牌桌缩略卡只显示图标与名称。

## 9. 动效规则

| 场景 | 目的 | 方式 | 时长 |
| --- | --- | --- | --- |
| 页面进入 | 建立空间层级 | 环境、人物、内容不同幅度的 transform 和 opacity | 500-950ms |
| 分类切换 | 表达内容替换 | 新内容淡入并横移 8-18px | 220-380ms |
| 按钮悬停 | 操作反馈 | 局部高光和 2-6px 位移 | 160-220ms |
| 弹窗打开 | 聚焦决策 | 背景模糊、容器上移 12px | 220ms |
| 图标悬停 | 增强辨识 | 图标放大至 1.04，轮廓轻亮 | 180ms |
| 共同揭晓 | 看清本拍结算 | 小卡入场、真实倒计时条、旧牌左移堆叠 | 最少 3000ms |

- 只动画 `transform` 和 `opacity`。
- 循环动效只留给背景和低频氛围层。
- 禁止用动画遮掩等待、错误或禁用状态。

## 10. 页面蓝图

- 加载：全屏环境，中央短文案和一条低频光带。
- 初次档案：角色档案登记台。姓名与头像为主，隐私说明为次。
- 主菜单：人物海报加右侧卡牌切片导航，维持当前结构。
- 单人准备：独立镜头推进的训练部署页，不显示通用顶栏和人物 IP。左下是接近平方占位的圆形战术感应器，圆心只显示当前档图标；下方三档文字沿不可见圆周轮换，不绘制实体圆盘，当前档正对镜头，另外两档后退、缩小、偏转并轻度虚化。切换时替换圆心图标并带动感应器由呼吸、扫描或锁定状态过渡，默认选择中档。标题、本机席位、规则选择与每回合时间在右侧组成部署信息列，主动作固定在右下，不使用装饰性竖线或开发阶段说明。
- 本地正式牌桌：沿准备页环境继续推进镜头，不显示通用顶栏。上层采用斗地主式椭圆牌桌，2—6 个席位沿桌边排布；当前出招以图标加名称的小卡贴近各自席位呈现，不使用大字块。揭晓前绝不显示对手具体招式，揭晓至少停留 3 秒且倒计时条与真实阶段同步；进入下一拍后，最近三拍按 iOS 后台卡片式向左缩小、降饱和并增加景深。本人资源与三行 33 张招式牌位于下层，牌面只显示正式图标与名称；费用、门槛和简介留给后续悬停详情。主动作固定为右下“确认出招”。
- 好友房入口：进入通讯频道的仪式感；创建和加入为两种明确路径。
- 好友房大厅：六个席位组成空间阵列，房主动作与准备状态清楚。
- 结算：结果先于名单；赢家使用聚光和头像，名单退居下方。
- 设置：共享舞台镜头推进，整屏右强左弱的薄玻璃，分类和内容分层切换。
- 规则图鉴：像招式档案馆。图标、名字和费用先被读到，说明和条款逐层展开；不做数据表格或后台查询页。

## 11. 素材与来源

- 现有三层原创菜单素材可跨非对战页复用。
- 参考图只学习红黑硬边、冰青高光和非对称构图，不复制角色、服装、品牌或专有 UI。
- 所有新招式图标由图像生成模型创建，保存到仓库并经过缩小检查。
- 禁止 SVG 临时美术进入本轮正式资产；HTML/CSS 只承担布局、状态和简单几何效果。

## 12. 验收

- 所有非对战页遵循同一颜色、形状、按钮和弹窗系统。
- 设置背景从右向左呈现高透明薄玻璃，左侧场景可见，右侧不是纯黑块。
- 设置分类和按钮在默认、悬停、焦点、选中、禁用时文字均可读。
- 33 个招式都有独立 PNG 图标，48px 与 28px 缩小检查通过。
- 规则图鉴首先像游戏内容，不像后台检索。
- 1000x650、1366x768、1920x1080 无关键操作遮挡和横向溢出。
- 关闭动效或透明度偏好后信息完整。
- 桌面类型检查、构建、导航和素材白名单检查通过。
- 使用真实 Electron 逐页点击检查；本地正式牌桌还需验证三档难度点击、四档时间、33 张牌三行布局、选择提交和双方揭晓。
