# DeiDei 桌面端设计标准

状态：R04-T01-b 视觉规范；R04-T02-d 落实字号与职责 CSS；R04-T03-a 的实际动态检查及设备边界见 [执行结果](../../docs/results/R04-T03-a/REPORT.md)。

frontmatter 仅登记已实现的共享控件 token，既有大厅身份与页面规范继续沿用正文；控件运动 token 见 `.impeccable/design.json`，不改写整套设计系统。

## 1. 目的与边界

- 产品：朋友之间玩的二次元战术卡牌游戏，不是网站、数据后台或通用桌面工具。
- 第一印象：红黑动态海报、冰青折射、轻薄玻璃、清楚的战术层级。
- 主要玩家：第一次打开游戏的本地玩家，以及邀请朋友进入房间的玩家。
- 本轮覆盖：加载、初次档案、主菜单、单人准备、本地正式牌桌、联机前厅、创建／加入、好友房大厅、多人入场、正式多人战局、结算、设置、经典规则图鉴、弹窗及错误状态。
- 本轮排除：公网服务部署、真实异地多客户端验收、聊天、邀请链接、公开房间、好友列表与多人 AI。
- 行为边界：不改变规则、招式语义、联机协议、存档、worker、CSP、Electron 权限或 TLS。

## 2. 设计读法

- 模式：在现有 DeiDei 品牌上的视觉重构，保留信息架构和真实操作。
- `DESIGN_VARIANCE: 8`：非对称海报构图，避免页面都变成居中卡片。
- `MOTION_INTENSITY: 7`：有镜头推进、分层切换和明确反馈，不做无目的循环特效。
- `VISUAL_DENSITY: 6`：菜单留白，图鉴和大厅承载更多信息，但仍保留清楚的主次。
- 技术：React 19 加原生 CSS。没有运行时 UI、图标或动画依赖。

## 3. 视觉身份

### 色彩

| 角色 | 值 | 用法 |
| --- | --- | --- |
| 夜色底 | `#080b10` | 页面深色底与遮罩 |
| 炭黑 | `#121922` | 次级表面 |
| 主红 | `#ef3f56` | 唯一主强调色、主动作、攻击 |
| 暗红 | `#8f1e31` | 红色阴影与按下态 |
| 冰青 | `#83e6f1` | 信息折射、焦点与联机 |
| 主文字 | `#f7f4ed` | 标题与关键标签 |
| 次文字 | `#a9b3bd` | 说明、元信息 |

- 红色只表达主动作、危险或攻击能量。
- 冰青表达焦点、联机和玻璃折射；卡牌分类按下方独立配色。
- 禁止新的紫蓝渐变、纯黑大块、纯白大块和多套强调色竞争。

### 字体

- 使用系统无衬线字体，不新增字体文件。
- 展示标题：紧凑、粗体、负字距，可压在人物后方。
- 页面标题：36-64px，最多两行。
- 正文：15-17px，行高 1.6-1.8；1366×768 下仍以 15px 为默认阅读基线。
- 玩家名、按钮、资源名、招式名和回合状态属于关键操作信息，默认 12-16px，不得为了塞入布局降成装饰小字。
- 元信息：10-12px，只用于次要状态、分类和快捷提示；8-9px 仅允许非必要英文索引，不能独立承载玩法信息。
- 中文为主，英文只作为短标签，不用无意义版本戳和装饰句。

### 形状

- 主动作：硬边斜切，圆角为 0-2px。
- 表面与弹窗：硬边矩形，最多 2px 圆角，依靠折射边而非圆润卡片表达层级。
- 头像保留现有纸绘外形，作为唯一可明显柔和的元素。
- 不使用通用胶囊按钮、三张等宽网页卡片和大面积实色面板。

## 4. 背景与玻璃

### 分层舞台

合成顺序：环境图、缓慢光晕、标题、氛围碎片、人物、真实 UI。人物可以穿过标题，但不得盖住按钮和正文。

- 主菜单：环境完整可见，人物为第一视觉焦点。
- 二级页：环境轻微推进或偏移；页面内容接替人物成为信息焦点。
- 同一张环境图可复用，但每页用裁切、位置、光区和内容结构形成不同场景。
- 背景缺失时使用红黑 CSS 渐变，交互仍必须完整。

### 整屏薄玻璃

- 设置页玻璃属于整屏背景层，不是右侧一块黑面板。
- 玻璃从右向左渐隐：右侧折射最清楚，越向左越透明，左侧背景与人物保持可见。
- 环境图本身先做 3px-5px 景深失焦，再叠加 `blur(18px-24px) saturate(112%-125%)` 的渐隐折射；模糊必须肉眼可见，背景色总透明度不高于 12%。
- 内容镜片只增加细边、内高光与局部阴影，不重新铺一层大色块。
- `prefers-reduced-transparency` 下使用高对比实体深色，保证文字可读。

## 5. 布局骨架

- 页面安全边距：桌面 42-84px，窄屏 22-32px。
- 主验收尺寸：1366x768；兼容 1000x650 和 1920x1080。
- 非对战二级页优先使用一主一辅的非对称结构，不复用同一张居中纸卡。
- 主要动作必须在首屏可见。
- 小于 820px 时改为单列，先信息后装饰；装饰层可降低透明度或隐藏。

R04-T03-a 使用现有安全边与裁切焦点：欢迎工具命中 `.welcome-scene` 的真实 DOM；牌桌安全边为 `--arena-safe-x`，本地与联机共用布局。1000×650 内容区的 33 招式采用图标在上、文字在下，卡名字号至少 12px，字形与标签保留可读空间。短窗口的待选卡高 160px，与共用选择舞台配合。小于 600px 高的内容区提供表单／牌桌纵向滚动，欢迎表单在卡片内滚动；此为更小内容区的回退，不代表移动端验收。

出牌终点取 `.self-seat .move-target` 的实际中心。`BattleStage` 用 ResizeObserver 写入 arena 内的百分比 CSS 属性，不逐帧更新 React；窗口或舞台尺寸变化后仍以当前本人席位为终点。隐藏目标不属于公开历史，也不参与历史计数。resize 不创建新会话，既有会话状态继续推进牌局与入场。

此前图鉴性能优化只适用于较低画面档位；2026-10-04 Teddy 指定恢复完整效果作为最高档：完整动态恢复共享舞台 transform/filter 镜头与四项环境循环；完整装饰恢复3px背景失焦、人物阴影、卡牌逐层brightness／saturate／blur和四边自然渐隐；完整玻璃恢复档案22px毛玻璃。渐隐作用于sticky内容层，统一滚动条保持清晰可拖动。均衡／流畅继续暂停图鉴环境循环、减少镜头插值与逐层滤镜／mask，玻璃按6px／关闭降级。系统减少动态／透明度优先。性能判断仍使用普通main、1920×1080、DPR2、焦点明确的固定八次滚轮对照，不以构建通过宣称性能通过。

## 6. 按钮层级

### L1 主动作

用途：开始对局、创建房间、保存并关闭、再来一场。

- 外观：主红斜切或红色能量边，最少 48px 高；一个页面同一时刻只出现一个最强主动作。
- 悬停：向操作方向位移 2-6px，文字下方扫过一次高光，边缘短暂点亮。
- 按下：回缩 1-2px 或缩放到 0.98。
- 焦点：冰青双层轮廓，不依赖颜色变化。
- 禁用：保留文字和轮廓可读性，不仅降低透明度。

### L2 场景动作

用途：好友联机、加入房间、确认设置分类中的主要选择。

- 外观：炭黑透明切片，冰青细边和轻微内折射。
- 悬停：短距离抬升或横移，局部高光，不整块变白。
- 动效时长：160-220ms。

### L3 工具动作

用途：返回、关闭、搜索辅助、复制房号、设置、规则入口。

- 外观：透明底、文字、细分隔线或单侧导轨。
- 悬停：文字和细线提亮，位移不超过 4px。
- 不使用主动作的红色填充、扫光、外发光或大面积底纹。
- 返回按钮按 Teddy 2026-10-05 澄清，以图鉴样式为共享标准：`ui-back` 统一冰青箭头、直角薄边、48px 高度、15px／700字重、13px箭头槽、10px间距和25px左右内边距。使用 `SharedUI.BackButton` 按字符数设置宽度（75px＋每字符15px），不接受页面最小宽度／网格拉伸；五字“返回主菜单”与“回到 bi”均为150px，同字数文案同宽，较长文案相应加宽，页面只控制位置。单人、设置、图鉴（含内部回到上一张）、好友房、欢迎预览与教程／结算均复用。玻璃按全站档位统一：full为12px／135%饱和，light为6px／110%，off及系统减少透明为不透明深底且悬停仍不透明；减少动态停用插值。页面通用按钮选择器不得另改宽度、字形或质感。 返回验收须注明运行工作区与画面档位，分别核对按钮本体、文字、伪元素和祖先层；旧分支的页面过滤规则不得遗漏好友联机。房间既有暗角和导航暗底与按钮自身玻璃分别验收，不通过改页面暗罩代替组件统一。

### L4 危险动作

用途：退出游戏、离开房间、放弃修改、重建档案。

- 默认：低调红色描边或文字，不与 L1 同时争夺视觉焦点。
- 触发不可逆结果前使用确认弹窗。
- 确认按钮明确写出结果，如“确认退出房间”，不使用模糊的“确定”。

### L5 图标动作

用途：关闭、暂停、冻结、局势和席位通信。

- 最小点击区 36x36px，图形居中。
- 默认透明，悬停只出现局部折射底与焦点轮廓。
- 不将字符颜色与背景同时提亮，任何状态都必须看清标签或图形。

### 通用状态

- 默认、悬停、按下、键盘焦点、禁用、忙碌必须齐全。
- 高光永远位于文字下方，按钮文字在独立上层。
- 桌面按钮标签保持单行。
- `prefers-reduced-motion` 下取消位移、扫光和错峰，仅保留颜色、边线和焦点。

### 规则选择按钮

- 单人准备和好友房部署共用 `SharedUI.RuleButton`：沿用原浅冰青左亮边、从左向右渐隐的轻底纹和上下内高光，与时长选择保持相同高度；版本仍为经典规则 1.0.1。
- 当前只实现按钮外观，固定 `aria-disabled="true"` 并说明规则选择界面待加入；没有选择页面或点击回调。忙碌／阻断状态另使用原生 `disabled`，不可把可聚焦外观描述为已支持切换规则。

## 7. 页面组件

### 导航与分类

- 当前项使用单侧导轨、清晰白字和短距离位移。
- 悬停和选中强调放在前景文字、导轨与短线，不在文字背后铺白色或大面积高亮底。
- 未选项降低层级，但文字对比度不低于正文标准。
- 分类切换用 220-380ms 的淡入加 8-18px 位移，表达内容已替换。

### 表面与信息块

- 只有真实层级需要承载面时才使用玻璃或边框。
- 多项信息优先用留白、分组、大小和线性导轨，不把每段文字装进卡片。
- 同页最多一个主玻璃表面；其余区域使用透明底或局部折射。

### 表单

- 全站标准文字输入使用 `SharedUI.TextInput` 与 `styles/controls.css`，视觉取自图鉴搜索：直角、分层渐变、薄亮边，悬停内光，焦点展开底边高光。搜索图标和清空是搜索用途的附加操作。图鉴搜索、欢迎、设置昵称、好友房房间号与密码已接入；房间号保留大号字与字距，密码保留原生密码输入。标签、长度限制、校验和禁用仍由调用方提供。

- 标签位于输入上方，帮助文字位于输入下方。
- 输入使用深色透明镜片和明亮文字。聚焦沿用图鉴的薄边提亮、底边高光与内光，不增加外层蓝色 outline／描边或第二层输入底板；页面局部样式不得覆盖共享文字输入的焦点外观。
- 错误就近显示，保存失败不得覆盖输入。
- 滑杆、复选框、头像选择都提供 hover、active、focus 和 disabled 状态。

### 时长选择

- `SharedUI.TurnTimeSelector` 使用 fieldset／legend 和同组原生 radio；整档标签可点击，保留方向键选择、可见焦点和禁用语义。等宽档位排列在透明薄导轨上，当前档下方的小光点与局部光晕平滑滑动（320ms），不铺厚底板。
- 单人当前仅不限时可用，其余显示档禁用；好友房创建及后续每拍时限弹窗读取服务端 `allowed_turn_ms`，未收到能力时仅保留当前值。共享外观不新增时长能力、不更改计时或提交接口。

### 复选框与下拉选择

- 原生 checkbox 采用透明直角空框；选中时边缘加粗（2px），内部显示实心冰青方块，不绘制勾号。悬停提亮、按下轻缩、键盘焦点外移，禁用保持状态可辨；沿用原生 Space 与关联标签操作。
- `SharedUI.Select` 基于 Electron 44 的原生可定制 select（`appearance: base-select`），保留原生键盘、焦点、选中与禁用行为。关闭时当前图标与文字并列，背景为分层渐变加顶部内高光；有图标时为图标留出左侧空间，不挤压标签。画面设置保留较紧凑的行高（最小34px），其他下拉控件为最小44px。
- 选项图标随 option 进入原生顶层 picker，不受设置面板或弹窗裁切。菜单使用不透明深色渐变，选中项用冰青小方块及底边标记；打开时淡入（180ms）并从上方轻移（220ms）。原生菜单不是另建的 React 浮层。
- `prefers-reduced-motion` 下关闭时长光点、复选框、下拉菜单／箭头／选项及外层底线的插值；状态、文字和焦点立即更新。只约定当前运行端的真实能力，不据此宣称其他浏览器或跨设备已验收。

### 滚动条

- 全站使用 `styles/controls.css` 的原生滚动容器自定义皮肤：透明轨道、直角冰青滑块，12px 拖动区域内显示 6px 细线；纵横方向一致，无系统灰色底板或圆角。
- 无溢出时不出现；有溢出时默认透明，容器悬停、键盘焦点、滚动或拖动时显示。滚动停止 800ms 后隐藏，仍悬停或聚焦时保留；显隐不改变容器尺寸。沿用原生键盘与拖动行为，不引入滚动库。
- 高对比模式保留可见滑块；减少动态不取消位置反馈。列表边缘渐隐与景深属于内容效果，独立于滚动条皮肤。

### 弹窗

- 背景：低透明黑色加 8-12px 模糊，仍看得到所在场景。
- 容器：深色薄玻璃，顶部一条冰青折射边，左下可带一条短红色能量边。
- 标题和关闭动作分层清楚，正文不超过约 65 个汉字宽。
- 操作从低到高排列：取消、次级、主确认；危险确认使用明确红色语义。
- 所有页面复用同一黑曜石战术终端外壳：斜切轮廓、渐隐电路纹样、冰青折射线和专用关闭键；不在页面内复制弹窗皮肤。
- 打开：毛玻璃背景与容器分别淡入，容器从下方 12-22px 进入；关闭反向淡出并轻微景深虚化，约 240ms。减少动态偏好下立即完成。

### 错误与空状态

- 错误条使用暗红透明底和高对比文字，保留重试或返回动作。
- 空状态说明“为什么为空”和“下一步能做什么”，不只显示一个图标。
- 加载使用与页面结构一致的光带或短文案，不使用无意义转圈。

## 8. 招式图标标准

- 数量：catalog 中 33 个招式一一对应，文件名使用 `entry_id`。
- 文件：透明 PNG，项目路径 `assets/moves/<entry_id>.png`。
- 构图：512×512，单一中心符号，最长边不超过 468px，外轮廓清楚。
- 颜色：攻击朱红／暗红，防御钴蓝／深蓝，技能翠绿／墨绿；少量铜金、象牙白作为局部亮边。整张牌面跟随分类色。
- 质感：沿用 2026-10-05 用户接受的 bi-v2 小样；暗色绘画纹理、铜金双边框、四角星纹、低对比天体弧线。主体以大形和两三块明暗区为先，局部有能量亮边，减少镜面高光、漂浮碎片和塑料材质。
- 禁止：文字、数字、品牌、复杂背景、细碎线条、相似度过高的重复轮廓。
- 缩小验收：在 48px 能直接区分，在 28px 仍能通过轮廓和主色识别。
- 相同招式家族保留母形；防御加入围护形，炸药、雷电与赠送版本增加局部来源标记。密集选择区同时显示原生修饰标签。
- 模型只生成无字卡框与透明图标；`scripts/export_card_art.py` 从 catalog 精确排入分类、E 编号和名称，导出 1080×1440 完整 PNG／WebP。字体为系统宋体，不分发字体文件。完整规则与费用继续从真实状态读取。
- 擂台选中牌、席位出牌记录、选牌历史、终场与图鉴示例／详情使用 `assets/cards/<entry_id>.webp`；密集手牌与资源／关系按钮使用透明图标和可访问的原生文字。强化资格保留实时标记，休整不在完整牌面上重复覆盖文字，手牌不额外显示“赠送”标签；未揭晓仍用既有牌背。席位完整牌面按 3:4 铺满，移除外层卡壳；双人揭晓尺寸随窗口宽高收敛，并保留身份和中央倒计时的间距。
- 验证与导出位置见 [本轮交付记录](../../docs/results/card-art-redraw/README.md)。

### 卡牌风格设置｜2026-10-06

设置增加独立“卡牌 / CARDS”，不混入画面质量档位。两组原生 radio 分别展示绘画牌面与原版卡牌，预览共用牌桌的卡框、资源及 catalog 名称；攻击／防御／技能各一张，以同一招式对照。硬边薄玻璃、系统字体、铜金选中边、冰青键盘焦点沿用现有 UI。说明和保存动作稳定留在阅读区，短窗口降低样张高度；更窄窗口自然纵向排列，不压小关键操作字号。

绘画牌面使用红／蓝／绿完整图片，原版恢复旧图标、原切角卡框及原生标题；手牌、资源、历史、图鉴和本地／联机共用牌桌一起切换。即时预览仅改变草稿，保存成功采用主进程回复；放弃恢复保存值，失败保留草稿与旧档案，保存中禁用操作。档案 v3 用独立 `cardStyle` 字段；合法 v1／v2 读取时保留原版，只有显式保存才写入，新建档案默认绘画牌面。系统减少动态／透明度仍优先。

## 9. 动效规则

| 场景 | 目的 | 方式 | 时长 |
| --- | --- | --- | --- |
| 页面进入 | 建立空间层级 | 环境、人物、内容不同幅度的 transform 和 opacity | 500-950ms |
| 分类切换 | 表达内容替换 | 新内容淡入并横移 8-18px | 220-380ms |
| 按钮悬停 | 操作反馈 | 局部高光和 2-6px 位移 | 160-220ms |
| 弹窗打开 | 聚焦决策 | 背景模糊、容器上移 12px | 220ms |
| 图标悬停 | 增强辨识 | 图标放大至 1.04，轮廓轻亮 | 180ms |
| 共同揭晓 | 看清本拍结算 | 大卡旋转收进席位、牌桌恢复清晰、旧牌左移堆叠；顶栏显示下一回合倒计时 | 本地 3000ms / 多人 5000ms |
| 单人入场 | 把部署页与牌桌连接成同一空间 | 外围全景沿中轴推进至竞技台，全员身份先到场，界面晚 600-900ms 接入 | 5000ms，按钮显示倒计时且可跳过 |
| 擂台交接 | 遮蔽竞技台与外围全景的素材差异 | 入场由深毛玻璃恢复清晰；终场先将擂台压入毛玻璃，再由终场外围全景恢复清晰 | 650-1050ms |
| 整场终局 | 明确胜利、阵亡与最后一拍 | 镜头由竞技台拉回外围，全员结果依次落位，最后一拍牌面随后显现 | 1800-2600ms |
| 终局返回 | 把整场结果交还主菜单 | 结果内容下沉淡出、镜头短暂推进后切回主菜单 | 600-800ms |

- 只动画 `transform` 和 `opacity`。
- 同一时刻只允许一层拥有同一组 `transform`；终局退出由背景包裹层接管镜头，内部尚未结束的入场动画冻结在当前帧，禁止重置后再播放退出。
- 依赖 `translate(-50%)` 居中的组件必须在所有关键帧保留该定位变换；终局背景在可见场景切换前完成预加载，禁止首帧空图。
- 循环动效只留给背景和低频氛围层。
- 禁止用动画遮掩等待、错误或禁用状态。

## 10. 页面蓝图

- 加载：全屏环境，中央短文案和一条低频光带。
- 初次档案：角色档案登记台。姓名与头像为主，隐私说明为次。
- 主菜单：人物海报加右侧卡牌切片导航，维持当前结构。
- 单人准备：独立镜头推进的训练部署页，不显示通用顶栏和人物 IP。左下是接近平方占位的圆形战术感应器，圆心只显示当前档图标；下方三档文字沿不可见圆周轮换，不绘制实体圆盘，当前档正对镜头，另外两档后退、缩小、偏转并轻度虚化。切换时替换圆心图标并带动感应器由呼吸、扫描或锁定状态过渡，默认选择中档。标题、本机席位、规则选择与每回合时间在右侧组成部署信息列，主动作固定在右下，不使用装饰性竖线或开发阶段说明。
- 单人开场：准备完成后先进入独立入场演出。生成式外围全景与正式竞技台保持同一中轴、材质和青左红右光源；镜头从入口平台向竞技台推进，两名玩家在场后再接入选卡界面。对阵身份使用独立头像徽记、能量轨迹、幽灵序号与镜像阵营色，不得回退为“头像＋名字塞进整条矩形横栏”的通用网页卡片；默认停留 5 秒，右下动作显示“立即进入（Ns）”并允许跳过。减少动态偏好下取消连续缩放，但仍保留身份与“进入擂台”信息。
- 本地正式牌桌：沿准备页环境继续推进镜头，不显示通用顶栏。顶端固定为“暂停｜回合状态｜冻结、局势”：中央写清回合数与选卡/等待/结算状态，结算剩余秒数下沉到擂台中央；竞技台背景在安全 HUD 边距内横向铺满，不再额外内缩。擂台首帧先由深毛玻璃景深恢复出场景与玩家，操作区延迟 600-900ms 再接入，禁止闪现手牌。擂台中央平时不承载摘要文字，结算倒计时只使用数字、短提示与薄光环，不放厚重矩形面板。单人暂停与冻结停止前端轮询、场景动画和操作，多人菜单不暂停服务端牌局且冻结禁用。暂停菜单提供继续、退出；多人额外提供只读的房间游戏设置预览，不伪造后端修改。
- 选择阶段以生成式栅格竞技台作为薄毛玻璃背景，上层待选大卡严格居中，不重复显示本机头像与昵称。待选卡保持足够尺寸，删去状态填充文案与廉价环形光效，只保留招式编号、分类、图标和名称。最多八拍历史牌在其左侧渐隐堆叠，悬停或键盘聚焦时相邻卡牌横向散开，目标牌轻微浮起但不改变原有前后遮挡关系。五类资源使用独立的“图标＋名称＋数量”标记，不再放进整条大卡片，也不另开资源详情窗；悬停和焦点只抬升当前资源。资源、出牌时间、三行 33 张招式牌与确认动作共同组成下层“操作区”。选择区牌名原则上不换行；“炸药、雷电、翻转、旋转、赠送”等修饰词使用独立的微型卡面标签，主体招式名另占一行。
- 提交后大卡旋转缩小至本人席位，本机身份同步平滑交接到底部；整个操作区向屏幕下方退场、降低景深并虚化，竞技台扩大后恢复清晰。2—6 个席位按人数单独调校而非等距套模板：双人使用更大的牌和字号、更紧凑的对阵距离；顶部外边距小于底部，本机底部留出更大安全距离；左右席位按竞技台透视单独调节。所有身份位于桌外侧、卡牌朝向桌心：顶部身份在上卡牌在下，左右身份在外卡牌在内，本机底部卡牌在上身份在下；上下身份组必须与对应牌面共用中轴，本机身份与当前牌面的可见间距控制在 10—18px。身份严格只显示头像和昵称，不添加背景、毛玻璃底板或席位按钮；悬停只轻微抬升头像并增强昵称亮度，不改变席位几何位置。
- 本地结算真实保留 3 秒、多人保留 5 秒；顶栏只显示回合和结算状态，不放阶段解释小字，下一回合倒计时放在擂台中央并作为结算阶段的主信息。进入下一拍后，席位最近三拍按 iOS 后台卡片式向左缩小、降饱和并增加景深。局势弹窗右栏仅承接可独立滚动的逐回合出招时间轴；左栏放全员资源和固定可见的本局淘汰记录，单人对局不显示淘汰记录，多人新开一局时重置。揭晓牌使用更大的异形正式卡面、内框与光泽，图标与牌名组成同一居中视觉组，牌名优先保证擂台视距下的可读性；选择区牌面只显示正式图标与名称，费用、门槛和简介留给后续悬停详情。主动作固定为右下“确认出招”。
- 好友联机依次使用固定页面名：L01 联机前厅、L02 房间部署、L03 房间接入、L04 房间大厅、L05 多人入场、L06 正式战局、L07 联机结算。前厅进入通讯频道，创建和加入是两条明确镜头路径；大厅以六个空间席位表达房主、准备和观众状态。
- L06 的擂台图、底层镜头、氛围和毛玻璃直接复用单人 `BattleStage`／`front-stage-table`，入场扩图不能继续作为正式擂台底图；只在 L05／L07 过渡使用。
- 联机 L01—L04 与主菜单共用持续挂载的 `menu-environment`、氛围和人物层；只调整父层镜头 transform，不换成独立中庭原画。L05／L07 使用持续挂载的擂台外围层，在毛玻璃峰值交接景别；战局至结果先保留最后公开牌桌失焦 650ms，结果返回先退场 720ms。镜头状态改变才重播玻璃，普通成员／重连快照不重播。多人入场沿用原 2.6 秒并可跳过；演出期间禁止选卡，但不停止服务端计时。
- 联机入口沿用 `menu-option` 主／次动作；返回沿用 `settings-back`；辅助动作沿用 `settings-action`；创建、加入和开局沿用 `prepare-start`。滑杆使用 `settings-range`，文本输入与设置页共享样式；原生 radio、checkbox、range 和可访问名称保留。不得另建联机按钮皮肤或通用动效框架。具体分镜见 `docs/prd/R04-ONLINE-CONTINUITY-PRD.md`。
- 多人正式战局必须复用 `.battle-table`、共享 `BattleStage`、正式卡面、操作区、局势弹窗与 2—6 人席位，不再维护 `.online-table`。联机菜单不暂停服务端回合，冻结不可用；多人揭晓时间由服务端状态决定。减少动态只取消连续镜头缩放和位移，保留入场、战局、结算的状态顺序；战局首帧不得先闪出操作区。
- 整场结算：删除纸张式结果页，改用竞技台外围全景承接镜头拉远。牌局确认终场后，清晰擂台先渐入深毛玻璃，再切换外围全景并由毛玻璃渐出，以遮蔽两张背景素材的透视差。胜利使用冰青聚光，阵亡使用红色断裂光；右上角玩家结果统一使用纯头像横排，姓名只在鼠标悬停或键盘聚焦时紧贴头像下方显示纯文字，不绘制提示底板、身份长条或状态面板。本机头像用冰青描边与光晕突出。最后一拍整体位于头像列下方并略向画面下部偏移，只展示玩家身份、双方招式与回合数，不输出内部规则摘要长文；终场三个操作靠右排列，并继续提供“局势回顾、再来一场、返回主菜单”，阵亡分支同样可复盘。返回主菜单必须先播放结果内容退场与镜头交接，不允许点击后硬切。
- 设置：共享舞台镜头推进，整屏右强左弱的薄玻璃，分类和内容分层切换。
- 规则图鉴：与设置共用分层舞台镜头和返回按钮，进入时推进，返回时拉回。左侧使用连续滚动的通知式层叠列表，上方卡牌盖住下方，越往下收窄、重叠和景深越强；滚轮只浏览，点击后将该牌平滑移到最前并打开攻略。最前方卡牌完整可见、保持大点击区域；右侧档案稳定阅读。搜索框和选牌列表均为直角；搜索框使用分层渐变，正常、悬停、聚焦分别呈现薄亮边、内光和展开的底部高光线。卡牌按第 8 节使用红／蓝／绿底色与铜金边框，分类颜色贯穿整张牌；选中保留亮边，取消表面扫光。滚动区两侧留出阴影缓冲，上下和左右边缘自然渐隐，最前卡牌始终位于清晰区。去掉搜索标题和底部快捷区；搜索右侧按钮切换卡牌／图标两种模式。图标模式使用直角方块密集展示招式，搜索、分类和当前选择两种模式共用。层叠展示放在原生 sticky 层，避免快速滚动时浏览器位移与 React 重排相互抵消；禁用滚动锚定自动补偿。列表的显示范围与堆叠拐点跟随实际容器高度：高窗口增加可见牌数，上段显示步距80px，小于最短88px卡面，相邻牌始终叠盖、上下不留空隙；压缩集中在底部。148px仅作为逻辑滚动步长。列表末尾或结果不足时允许自然留白，不拉伸卡面填充。
- 图鉴档案先显示白话作用、持有门槛、实际支出和关键风险；先看懂／精确属性使用通栏等宽大 Tab，顶边高光标识当前档案层；精确攻防、匹配范围、时序、完整限制可切换展开。关联卡牌最多三张首显并支持回到上一张；关联规则直达主题与原条款。第一次玩从攒、bi、普通防御开始，问题入口和术语按需阅读。右上角新增新手实战入口；先看三张牌、常见问题、完整规则各自打开原生弹窗，不替换当前档案。关闭弹窗保留卡牌与阅读位置，卡牌链接才跳转档案。
- 图鉴示例使用固定两人条件，播放准备、同步翻牌、效果、结果四步；格挡、回击和直接淘汰区分表现。动画、资源和休整状态只读取现有核心生成的静态账目，不在 renderer 重新计算规则，不写本机档案。场景统一排入单行横向滚动条，边缘自然渐隐，默认第一个；支持滚轮、横向触控与键盘定位，不设更多场景折叠。可重播、切换回合，减少动态时使用静态步骤。课间便签默认隐藏，悬停、聚焦或轻触可读；关键规则不藏在便签里。

## 11. 素材与来源

- 现有三层原创菜单素材可跨非对战页复用。
- 参考图只学习红黑硬边、冰青高光和非对称构图，不复制角色、服装、品牌或专有 UI。
- 所有新招式图标由图像生成模型创建，保存到仓库并经过缩小检查。
- 正式竞技台使用生成式 WebP 栅格资产；CSS 只负责裁切、渐隐、景深和状态切换，不用 SVG 或 CSS 几何图形代替主美术。
- 禁止 SVG 临时美术进入本轮正式资产；HTML/CSS 只承担布局、状态和简单几何效果。

## 12. 验收

- 所有非对战页遵循同一颜色、形状、按钮和弹窗系统。
- 设置背景从右向左呈现高透明薄玻璃，左侧场景可见，右侧不是纯黑块。
- 设置分类和按钮在默认、悬停、焦点、选中、禁用时文字均可读。
- 33 个招式都有独立 PNG 图标，48px 与 28px 缩小检查通过。
- 规则图鉴首先像游戏内容，不像后台检索。
- 1000x650、1366x768、1920x1080 无关键操作遮挡和横向溢出。
