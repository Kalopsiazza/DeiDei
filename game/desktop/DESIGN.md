# DeiDei 桌面端视觉规格

状态：R04-T01-b 主菜单第四轮与设置页首轮，已实现并完成本机热更新验收。

## 本轮执行计划

1. 将主菜单背景、标题、人物与氛围改成共享的分层舞台，让标题位于人物之后，人物保持视觉最上层。
2. 保留单人对局、好友联机的完整切片动效；将规则、设置、退出降为安静的文字导航，不复用主动作扫光与斜纹。
3. 设置页复用同一舞台。进入时分别推进环境、人物与前景层，形成带景深的镜头过场；设置内容延迟出现，返回时镜头复位。
4. 不引入 Three.js、动画库或新素材，先用现有三层位图与 CSS 3D transform 验证方向；关闭动效偏好时立即切页。
5. 保留设置字段、保存、脏数据关闭确认和键盘焦点，完成类型检查、构建及真实 Electron 点击检查。

## 目标与边界

- 页面：桌面端主界面 / 开始菜单。
- 目标：第一眼像完整的二次元卡牌游戏入口，而不是带人物背景的网页菜单。
- 主动作：开始单人对局；好友联机为第二动作。
- 保留：现有五个入口、档案数据、开发预览、键盘焦点与所有跳转行为。
- 不改：规则、网络、存档、worker、准备页、牌桌和结算页。
- 错误方向：单张大图烘焙全部内容、白色 iOS 毛玻璃、普通矩形按钮排在面板里、复制现有游戏角色或品牌。

## 参考与原创边界

主参考是用户提供的红黑二次元人物图，只学习高饱和红、近黑硬边、冰青高光和不对称人物构图，不复制角色、服装、姿势、武器或具体背景。

Minecraft 只用于理解现代游戏菜单的层级、可读性和背景氛围，不复刻其像素材质、Logo、按钮或世界观。最终素材必须是 DeiDei 原创角色与原创环境，不出现其他品牌标识、文字或水印。

## 方案选择

采用“分层动态海报”，不采用单张完整背景图，也不在首轮引入 Canvas / WebGL 场景。

- 位图负责角色与环境质感。
- CSS 负责轻微视差、光晕、粒子、卡牌碎片和交互反馈。
- UI 保持真实 DOM，保证焦点、禁用态和可读性。
- 当前内联 SVG 人物只作为第一轮验证稿；第二轮渲染树不再使用它。

## 原创女性 IP

- 定位：可爱、年轻但明确为成年人的原创二次元卡牌角色。
- 气质：亲近、灵动、自信，不是冷酷杀手，也不做幼态化或性感化表达。
- 识别点：银白偏淡粉的短发、珊瑚红与炭黑短外套、冰青卡牌饰件、手持一组无文字抽象卡牌。
- 画法：高完成度二次元游戏立绘，硬边块面与柔和脸部并存，局部印刷颗粒感。
- 禁止：校服、武器、真实品牌、文字、现有动漫 / 游戏角色相似脸或标志性服装。

## 素材分层

生成并在项目内保存三项正式位图素材：

1. `menu-environment.webp`：16:9 红黑抽象城市 / 室内舞台环境，无人物、无 UI、右侧保持暗部负空间。
2. `menu-character.png`：透明背景角色立绘，三分之二身或全身，人物主要朝向右侧菜单区域。
3. `menu-atmosphere.png`：透明背景前景氛围层，只含少量卡牌碎片、柔光和空间尘埃，不含文字。

合成顺序：环境图 → 缓慢移动的光晕 → 角色立绘 → 氛围层 → 标题与菜单。素材缺失时显示现有红黑 CSS 渐变，菜单仍可操作。

素材目标：环境图不超过 1.5 MB，角色不超过 2.5 MB，氛围层不超过 1 MB；不为首轮准备角色换装、多姿势、表情包或多套背景。

## 首屏构图

- 左侧约 58%：超大 `DeiDei` 标题与两段式 `攒一拍，再出招。` 副标题进入环境层，人物从文字上方穿过。角色是视觉焦点，文字不得压住脸。
- 右侧约 42%：无外层玻璃卡片的异形导航轨道。
- 主菜单不显示通用顶栏与左下档案卡；其他页面继续保留顶栏。开发预览收进右侧导航底部。
- 1366×768 为主验收尺寸；1000×650 仍需完整显示五个入口；1920×1080 不放大到空洞。

## 按钮语言

菜单按钮改为“卡牌切片导航”，融入右侧黑色斜切背景，不再像玻璃卡片：

- 每个入口是横向斜切条，左端共享一条细导轨，右端显示编号或快捷提示。
- 单人对局使用珊瑚红实色切片；好友联机使用炭黑切片与冰青边线；低频入口只保留文字、细线和编号。
- 悬停 / 键盘聚焦：切片向左抽出 6px，高光在文字下方扫过，右侧斜纹与编号点亮；不对整颗按钮使用亮度滤镜，保证文字始终清楚。
- 标题、状态栏和按钮加入冰青刻度、微型英文标记与细网格，形成战术终端语法，但不复制既有游戏品牌元素。
- 规则、设置、退出属于工具层，只使用细分隔线、短距离文字位移和清晰焦点，不使用切片轮廓、扫光、外发光或右侧斜纹。
- 按下：回缩 2px；禁用：保留轮廓和文字可读性，不只依赖透明度。
- 所有按钮继续使用原生 `button`，可见焦点环不得被 `clip-path` 裁掉。

## 动态效果

- 环境图：20–30 秒一次的极慢缩放和 8–12px 位移。
- 光晕：两层低透明径向渐变横向漂移，不能扫过文字造成闪烁。
- 粒子：少量低速微粒从左下向右上移动；不是满屏雪花或烟花。
- 角色：进入页面时 400–600ms 轻微上浮与显现；鼠标悬停时轻微上移、放大并出现冰青轮廓光，停稳后不持续晃动。
- 菜单：各项错开 30–45ms 进入；交互反馈不超过 180ms。
- 设置过场：环境、人物、氛围使用不同幅度的 `translate3d`、`scale` 与轻微 `rotateY`，约 900ms 完成镜头推进；设置面板在镜头开始后进入，不伪称真实 3D 场景。
- `prefers-reduced-motion: reduce` 下停止视差、漂移、粒子和错峰进入，仅保留颜色与焦点变化。
- 不新增动画库；使用 CSS `transform` 与 `opacity`，避免高频布局重排。

## 实现约束

- 复用当前 React 页面状态和按钮事件，只重写主菜单标记与样式。
- `build.cjs` 复制受控素材目录；`app://desktop/` 只提供明确允许的静态文件与 MIME 类型，禁止路径穿越和远程资源。
- CSP、权限拒绝、导航拦截和 worker / preload 接口保持不变。
- 实现范围：`renderer.tsx`、`style.css`、`build.cjs`、`dev.cjs`、`main.cjs`、`ui-assets.cjs`、`test-packaging.cjs`、`game/packaging/build.py` 与 `assets/menu/`。
- 不引入 UI、动画或图像运行时依赖。

## 验收标准

1. 主菜单不再渲染 SVG 人物，三层位图按顺序组合且无品牌 / 水印 / 乱码。
2. 视觉上首先读到原创女性 IP 和“单人对局”，按钮像游戏导航而不是网页卡片。
3. 背景、光晕和粒子有轻微持续动态，但文字和点击区域稳定。
4. 五个入口与开发预览行为保持不变；主菜单不显示通用顶栏和档案卡，键盘焦点、禁用态清楚。
5. 按钮悬停时文字对比度不下降，右侧纹理、高光扫过和角色悬停反馈均不改变布局。
6. 1000×650、1366×768、1920×1080 不出现菜单遮挡、角色压字或滚动条。
7. 关闭动效偏好后界面保持完整；素材缺失时 CSS 回退仍可操作。
8. 通过类型检查、构建、导航测试、素材协议 / 打包检查，并在真实 Electron 热更新窗口中完成视觉检查。
